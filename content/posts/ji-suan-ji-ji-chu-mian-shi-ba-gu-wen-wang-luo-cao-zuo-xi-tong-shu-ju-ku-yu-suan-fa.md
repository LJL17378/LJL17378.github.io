这份手册按全栈和大前端面试的实际使用频率组织。回答时不要只报定义，尽量说明：**它解决什么问题、核心机制是什么、有什么代价、在项目哪里见过。**

## 一、数据结构与算法

### 1. 如何分析时间复杂度和空间复杂度？

**回答：** 时间复杂度描述输入规模增长时，操作次数的增长量级；空间复杂度描述额外内存的增长量级。分析时保留最高阶项并忽略常数，例如两层各执行 n 次的循环是 `O(n²)`。需要区分最坏、平均和均摊复杂度。

### 2. 什么是均摊复杂度？

**回答：** 某次操作可能很贵，但在一长串操作中平均成本较低。例如动态数组扩容一次需要复制 `O(n)` 个元素，但按倍数扩容后，多次尾部追加的均摊复杂度仍是 `O(1)`。

### 3. 数组和链表有什么区别？

**回答：** 数组内存连续，支持 `O(1)` 随机访问，缓存局部性好；中间插入删除通常需要移动元素。链表节点分散，定位第 k 个元素是 `O(n)`，已知节点位置时插入删除可为 `O(1)`，但指针占空间且缓存不友好。

### 4. 栈和队列分别适合什么场景？

**回答：** 栈后进先出，适合函数调用、括号匹配、撤销和 DFS；队列先进先出，适合任务调度、消息缓冲和 BFS。双端队列允许两端插入删除，可用于单调队列和滑动窗口。

### 5. 哈希表为什么平均是 O(1)？

**回答：** 哈希函数把键映射到桶，可直接定位候选位置，所以平均查找接近常数。发生哈希冲突时可用链地址法或开放寻址法解决；冲突过多或装载因子过高会退化，因此需要扩容和良好哈希函数。

### 6. 哈希表和有序树如何选择？

**回答：** 只需要等值查询时哈希表通常更快；需要有序遍历、范围查询、前驱后继或稳定的 `O(log n)` 上界时，使用平衡搜索树。数据库索引还要考虑磁盘页，因此常使用 B+ 树。

### 7. 二叉搜索树为什么会退化？

**回答：** 如果输入接近有序，普通二叉搜索树可能变成链表，查找从 `O(log n)` 退化到 `O(n)`。AVL 树和红黑树通过旋转保持高度近似对数级。AVL 更严格平衡、查询稳定；红黑树调整通常更少，常用于通用有序容器。

### 8. 堆是什么？

**回答：** 堆通常是完全二叉树，最大堆保证父节点不小于子节点，最小堆相反。查看堆顶是 `O(1)`，插入和删除堆顶是 `O(log n)`。常用于优先队列、Top K、定时任务和堆排序。

### 9. BFS 和 DFS 有什么区别？

**回答：** BFS 按层扩展，通常使用队列，在无权图中能找到最短边数路径；DFS 沿一条路径深入，通常使用递归或栈，适合连通性、回溯、拓扑和枚举。二者时间通常都是 `O(V + E)`，空间取决于图结构和搜索前沿。

### 10. 什么是拓扑排序？

**回答：** 对有向无环图给出一个线性顺序，使每条边的起点都在终点之前。可用入度法：把入度为 0 的节点入队，依次删除它的出边；如果最终处理节点数少于总节点数，说明存在环。它适合任务依赖和构建顺序。

### 11. 常见排序算法如何比较？

| 算法 | 平均时间 | 最坏时间 | 额外空间 | 稳定性 |
| --- | --- | --- | --- | --- |
| 快速排序 | `O(n log n)` | `O(n²)` | 平均 `O(log n)` | 不稳定 |
| 归并排序 | `O(n log n)` | `O(n log n)` | `O(n)` | 稳定 |
| 堆排序 | `O(n log n)` | `O(n log n)` | `O(1)` | 不稳定 |
| 插入排序 | `O(n²)` | `O(n²)` | `O(1)` | 稳定 |

工程中的排序通常是混合算法，会针对小数组、近似有序输入和最坏情况做优化。

### 12. 快排为什么通常很快？

**回答：** 平均复杂度是 `O(n log n)`，原地分区且缓存局部性好，常数较小。选择随机枢轴或三数取中可以降低极端输入导致退化的概率。若必须保证最坏复杂度，可使用堆排序或内省排序。

### 13. 二分查找的关键是什么？

**回答：** 关键不是背模板，而是明确搜索区间定义和循环不变量。例如左闭右闭使用 `left <= right`，更新时排除 `mid`；寻找第一个满足条件的位置时，可把问题转换为单调布尔序列的边界查找。

### 14. 常见算法题型应掌握哪些模式？

- 哈希：两数之和、频次统计、去重。
- 双指针：有序数组、区间收缩、链表快慢指针。
- 滑动窗口：连续子数组或子串。
- 前缀和：快速求区间和。
- 单调栈：下一个更大元素、柱状图。
- 回溯：排列、组合、子集。
- 动态规划：状态、转移、初值和遍历顺序。
- 图：BFS、DFS、并查集、拓扑排序、最短路。

### 15. 动态规划与贪心有什么区别？

**回答：** 动态规划保存重叠子问题的最优结果，通过状态转移获得全局最优；贪心每一步选当前看起来最优的选择，只有满足贪心选择性质时才正确。无法证明局部最优能推出全局最优时，不应凭感觉使用贪心。

### 16. LRU 缓存如何实现？

**回答：** 哈希表负责 `O(1)` 定位节点，双向链表维护最近使用顺序。访问或更新节点时移到链表头，容量满时删除尾部节点，并同步删除哈希表记录。两种结构必须保持一致。

## 二、操作系统

### 17. 进程、线程和协程有什么区别？

**回答：** 进程是资源分配和隔离单位，拥有独立虚拟地址空间；线程是 CPU 调度的基本执行单位，同一进程内共享内存和文件等资源；协程是用户态的协作式任务，由运行时在明确的挂起点切换，切换成本通常更低。

### 18. 进程间如何通信？

**回答：** 常见方式有管道、消息队列、共享内存、信号、Socket 和文件。共享内存吞吐高，但需要同步；Socket 可跨机器，通用但协议和拷贝成本更高。选择取决于数据量、可靠性、通信范围和复杂度。

### 19. 线程共享什么，不共享什么？

**回答：** 同一进程的线程共享代码段、堆、全局数据和打开的文件；每个线程有自己的栈、寄存器、程序计数器和线程局部存储。共享内存带来通信便利，也带来数据竞争。

### 20. 什么是上下文切换？

**回答：** CPU 从一个任务切换到另一个任务时，需要保存和恢复寄存器、程序计数器等状态，还可能影响 CPU 缓存和 TLB。线程或进程过多会增加切换成本，因此并发数并非越大越好。

### 21. 并发和并行有什么区别？

**回答：** 并发是多个任务在一段时间内交替推进；并行是多个任务在同一时刻真正同时执行。单核也可以并发，多核才能让多个 CPU 任务并行。异步主要改善等待型任务的并发，不直接增加 CPU 算力。

### 22. 什么是竞态条件？

**回答：** 多个执行单元并发访问共享状态，结果依赖不可预测的执行顺序，就产生竞态。解决方法包括互斥锁、原子操作、消息传递、不可变数据和减少共享状态。锁只保护共同约定的临界区，遗漏任何访问仍会出错。

### 23. 互斥锁、读写锁、信号量和条件变量有什么区别？

- 互斥锁：同一时刻只允许一个执行者进入临界区。
- 读写锁：允许多个读者或一个写者，适合读多写少。
- 信号量：维护许可数量，可限制并发资源数。
- 条件变量：让线程等待某个条件成立，通常与互斥锁配合。

### 24. 死锁的四个必要条件是什么？

**回答：** 互斥、占有且等待、不可剥夺、循环等待。破坏任一条件可预防死锁，例如统一锁顺序破坏循环等待，或一次申请全部资源减少占有且等待。

### 25. 用户态和内核态是什么？

**回答：** 用户态权限受限，普通应用运行在其中；内核态可访问硬件和关键内存。应用通过系统调用请求文件、网络和进程管理等内核服务。用户态与内核态切换有成本，但与进程上下文切换不是同一个概念。

### 26. 什么是虚拟内存？

**回答：** 每个进程看到独立、连续的虚拟地址空间，操作系统通过页表映射到物理内存。它提供进程隔离、地址空间抽象、按需加载和共享页面，也允许暂时把不活跃页面换出到磁盘。

### 27. 什么是缺页中断？

**回答：** CPU 访问的虚拟页当前没有有效物理映射时触发异常，操作系统判断访问是否合法；若合法，则从磁盘加载或分配页面，更新页表后重新执行指令。若内存不足，可能需要置换其他页面。大量缺页会造成抖动。

### 28. 什么是 TLB？

**回答：** TLB 是页表映射的高速缓存，避免每次地址转换都多次访问内存。上下文切换和大工作集可能降低 TLB 命中率；大页可以减少页表项数量，但会增加内部碎片和管理取舍。

### 29. 堆和栈有什么区别？

**回答：** 栈通常保存函数调用帧和局部变量，由调用约定自动管理，分配快但空间有限；堆用于动态分配、生命周期灵活，由分配器和程序或垃圾回收器管理，可能产生碎片。这里的“堆”内存区域与“堆”数据结构不是一个概念。

### 30. 什么是 I/O 多路复用？

**回答：** 一个线程可以等待多个文件描述符的就绪事件，而不为每个连接创建一个阻塞线程。Linux 常见机制有 `select`、`poll` 和 `epoll`。`epoll` 通过内核维护关注集合和就绪列表，适合大量连接中只有少量活跃的场景。

### 31. select、poll、epoll 有什么区别？

**回答：** `select` 的描述符数量和表示方式受限制，每次调用需传递并扫描集合；`poll` 取消固定数量限制，但仍线性扫描；`epoll` 注册关注事件后获取就绪列表，避免每次扫描全部连接。实际性能还取决于连接活跃度和应用模型。

### 32. 什么是零拷贝？

**回答：** 零拷贝不是完全没有任何复制，而是减少数据在用户态和内核态之间的无谓复制及上下文切换。例如 `sendfile` 可让文件数据从页缓存直接进入 Socket 发送路径，适合静态文件传输。

### 33. 阻塞、非阻塞、同步、异步如何区分？

**回答：** 阻塞/非阻塞描述调用在结果未就绪时是否立即返回；同步/异步描述结果由调用方主动等待，还是完成后通过回调、事件等方式通知。四个概念经常组合出现，不能简单把非阻塞等同于异步。

## 三、计算机网络

### 34. OSI 七层和 TCP/IP 模型如何对应？

**回答：** OSI 包含物理、数据链路、网络、传输、会话、表示、应用七层。实际互联网常用 TCP/IP 分层：链路层、网际层、传输层、应用层。HTTP 位于应用层，TCP/UDP 位于传输层，IP 位于网际层，以太网/Wi-Fi 位于链路层。

### 35. 从输入 URL 到页面显示发生了什么？

**回答：** 浏览器解析 URL，检查缓存和相关策略；通过 DNS 获取地址；建立传输连接，HTTPS 还要进行 TLS 握手；发送 HTTP 请求；经过 CDN、代理和服务端处理后返回响应；浏览器解析 HTML，获取 CSS、JS 和图片，构建 DOM/CSSOM、布局、绘制与合成，并执行脚本和框架渲染。

面试中应根据追问展开，不要一开始把所有细节一次背完。

### 36. TCP 和 UDP 有什么区别？

**回答：** TCP 面向连接，提供可靠、有序的字节流，并实现流量控制和拥塞控制；UDP 无连接，保留报文边界，不保证到达和顺序，头部与状态更少。实时音视频、DNS 等可基于 UDP 自己实现需要的可靠性；HTTP/3 的 QUIC 也构建在 UDP 上。

### 37. TCP 为什么需要三次握手？

**回答：** 三次握手让双方确认彼此的发送和接收能力，并同步初始序列号。两次不足以让服务端确认客户端收到了自己的初始序列号，也更难避免旧连接请求造成错误状态。

### 38. TCP 为什么通常四次挥手？

**回答：** TCP 是全双工，关闭一个方向和关闭另一个方向可以分开发生。收到 FIN 只代表对方不再发送，本方可能仍有数据要发，所以 ACK 和本方 FIN 通常分开。若恰好没有剩余数据，也可能合并发送。

### 39. TIME_WAIT 有什么作用？

**回答：** 主动关闭方等待两倍最大报文生存时间，一是确保最后的 ACK 丢失时还能重发，二是让旧连接的延迟报文从网络中消失，避免污染相同四元组的新连接。大量 TIME_WAIT 需要从连接复用、短连接数量和端口范围等方面分析。

### 40. TCP 如何保证可靠传输？

**回答：** 通过序列号、确认应答、校验、超时重传、快速重传、滑动窗口和乱序重组。可靠不代表永不失败，应用仍需处理连接中断和不确定结果。

### 41. 流量控制和拥塞控制有什么区别？

**回答：** 流量控制保护接收方，接收窗口表示还能接收多少数据；拥塞控制保护网络，根据丢包、延迟等信号调整发送速率。实际发送窗口受两者共同限制。

### 42. TCP 粘包是什么？

**回答：** TCP 是字节流，没有消息边界。发送方多次写入的数据，接收方可能一次读到，也可能拆成多次读到。应用协议必须自行划分消息，可用固定长度、分隔符、长度前缀或自描述格式。UDP 保留报文边界。

### 43. HTTP/1.1、HTTP/2 和 HTTP/3 有什么区别？

**回答：** HTTP/1.1 支持持久连接，但同一连接上的请求处理能力有限，浏览器常开多个连接。HTTP/2 使用二进制分帧和多路复用，并压缩头部，但多个流共享一个 TCP 连接，丢包可能造成传输层队头阻塞。HTTP/3 基于 QUIC，为流提供更独立的传输，并改善握手和连接迁移。

### 44. HTTP 常见缓存头有哪些？

**回答：** `Cache-Control: max-age` 控制新鲜时间；`no-cache` 表示使用前需要重新验证，并非完全不缓存；`no-store` 表示不应存储；`ETag/If-None-Match` 和 `Last-Modified/If-Modified-Since` 用于协商缓存，未变化可返回 `304`。

### 45. Cookie、Session、Token 有什么区别？

**回答：** Cookie 是浏览器保存并按规则自动携带的小段数据；Session 通常指服务端保存会话状态，Cookie 只存会话 ID；Token 是客户端持有的访问凭证，可以是有状态随机串，也可以是 JWT。它们不是互斥概念，JWT 也可以存入 Cookie。

### 46. HTTPS 提供了什么？

**回答：** TLS 为传输提供机密性、完整性和服务端身份认证，客户端证书还可提供双向认证。它不能自动保证服务端业务安全，也不能防止终端本身被攻破。

### 47. TLS 握手的大致过程是什么？

**回答：** 客户端发送支持的版本、算法和随机参数；服务端选择参数并发送证书；客户端验证证书链和域名；双方通过密钥交换得到会话密钥；之后使用对称加密传输应用数据。TLS 1.3 减少了握手往返并移除了部分旧算法。

### 48. 数字证书解决什么问题？

**回答：** 证书把域名等身份与公钥绑定，并由受信任 CA 签名。浏览器验证证书链、有效期、域名和吊销状态，从而降低中间人伪装服务端的风险。证书本身不用于加密整个大文件。

### 49. DNS 解析过程是什么？

**回答：** 浏览器和操作系统先查本地缓存，再询问递归解析器；若无缓存，解析器从根、顶级域和权威 DNS 逐级获取结果，并按 TTL 缓存。实际系统可能使用 CNAME、负载均衡和 CDN 调度。

### 50. 正向代理和反向代理有什么区别？

**回答：** 正向代理代表客户端访问外部服务，服务端通常看到代理；反向代理代表服务端接收请求，客户端不必知道真实后端。Nginx 常用于反向代理、TLS 终止、负载均衡、静态文件和缓存。

### 51. CDN 为什么能加速？

**回答：** CDN 把可缓存内容放到靠近用户的边缘节点，减少网络距离和源站压力，并可进行连接优化与安全防护。动态内容仍可能回源；缓存键、过期和刷新策略设计不当会造成旧数据或命中率低。

### 52. 长轮询、SSE 和 WebSocket 有什么区别？

**回答：** 长轮询由客户端发请求，服务端等到有数据或超时后返回，再立即发下一次；SSE 在一个 HTTP 响应上持续推送文本事件；WebSocket 建立全双工通道。通知和模型输出适合 SSE，双向高频交互适合 WebSocket。

## 四、数据库基础

### 53. 关系型数据库和 NoSQL 如何选择？

**回答：** 关系型数据库擅长结构化关系、事务、约束和复杂查询；NoSQL 是多类系统的统称，可针对键值、文档、列族或图关系优化扩展和访问模式。选型应从数据模型、一致性、查询和运维需求出发，不能简单按“数据量大”决定。

### 54. 数据库三大范式是什么？

**回答：** 第一范式要求属性原子；第二范式要求非主属性完全依赖候选键；第三范式要求非主属性不传递依赖候选键。范式减少冗余和更新异常，读性能要求高时也可有意识反范式，但要承担一致性维护成本。

### 55. 主键、唯一索引和普通索引有什么区别？

**回答：** 主键唯一且非空，用于标识一行；唯一索引保证列组合不重复，NULL 行为取决于数据库；普通索引用于加速查询但不保证唯一。索引能加速读取，也会占空间并增加写入维护成本。

### 56. 索引为什么会失效或不被选择？

**回答：** 常见原因包括不满足联合索引前缀、对索引列做函数或隐式类型转换、前导模糊匹配、选择性太低、数据量很小，或优化器判断全表扫描成本更低。应以执行计划和实际统计为准。

### 57. 事务隔离解决哪些问题？

**回答：** 脏读是读到未提交数据；不可重复读是同一事务两次读同一行结果不同；幻读是按条件两次查询出现或消失了记录。更高隔离级别减少异常，但可能增加锁、冲突和重试。

### 58. 乐观锁和悲观锁是什么？

**回答：** 悲观锁先锁住资源再操作，适合冲突频繁且事务短的场景；乐观锁读取时不加排他锁，更新时检查版本号，冲突后重试或提示用户，适合冲突较少的场景。

```sql
UPDATE account
SET balance = ?, version = version + 1
WHERE id = ? AND version = ?;
```

受影响行数为 0 表示版本冲突。

### 59. undo log、redo log、binlog 分别做什么？

**回答：** 在 MySQL/InnoDB 中，undo log 支持回滚和 MVCC 旧版本；redo log 记录页修改，用于崩溃恢复和持久性；binlog 是 Server 层逻辑日志，用于复制和时间点恢复。它们层次和用途不同。

### 60. 为什么不建议深分页？

**回答：** `LIMIT 100000, 20` 通常需要扫描并丢弃前面大量记录，数据变动还可能造成重复和遗漏。可使用基于稳定排序键的游标分页，例如记住上一页最后的 `(created_at, id)`。

### 61. 数据库连接池解决什么问题？

**回答：** 建立数据库连接成本较高，连接池复用连接并限制并发，避免每个请求都新建连接，也保护数据库不被过多连接压垮。池耗尽通常说明慢查询、事务过长、连接泄漏或容量不匹配。

## 五、编程语言与运行时

### 62. 编译型和解释型语言有什么区别？

**回答：** 编译是把源代码提前转换为目标代码；解释是运行时逐步执行某种中间表示或源代码。现代语言常混合使用，例如 JavaScript 引擎会解释并即时编译热点代码，Python 通常先编译成字节码再由虚拟机执行。这个分类不是绝对二分。

### 63. 静态类型和动态类型是什么？

**回答：** 静态类型在运行前进行主要类型检查，动态类型在运行时确定值和操作是否合法。TypeScript 提供静态检查，但类型在编译后大多被擦除，因此外部输入仍需运行时校验。

### 64. 什么是垃圾回收？

**回答：** 垃圾回收自动识别不再可达的对象并回收内存。常见思想包括引用计数和追踪式标记清除；现代运行时还会基于对象“多数朝生夕死”的规律做分代回收。GC 减少手动释放错误，但仍可能有停顿、内存峰值和逻辑泄漏。

### 65. 内存泄漏是什么意思？

**回答：** 程序不再需要某块内存，但它仍被引用或无法释放，导致占用持续增长。前端常见来源有未清理定时器、事件监听、闭包和无限缓存；服务端常见来源有全局集合、连接未关闭和无界队列。

### 66. 深拷贝和浅拷贝有什么区别？

**回答：** 浅拷贝只复制第一层，嵌套对象仍共享引用；深拷贝递归复制整个对象图。深拷贝要处理循环引用、日期、Map、Set、原型和函数等，JSON 序列化不是通用深拷贝方案。

### 67. 序列化和反序列化是什么？

**回答：** 序列化把内存对象转换为可存储或传输的格式，反序列化则恢复。JSON 可读性和兼容性好，但类型表达有限；Protobuf 体积小、解析快且有 Schema，但调试和演进需要规范。反序列化不可信数据必须校验，某些原生对象格式还可能导致代码执行风险。

## 六、Linux 与工程基础

### 68. 文件描述符是什么？

**回答：** 文件描述符是进程访问文件、Socket、管道等内核对象的整数句柄。每个进程有描述符表。连接泄漏往往表现为文件描述符耗尽，因此服务要正确关闭资源并监控上限。

### 69. Linux 文件权限如何理解？

**回答：** 权限分为所有者、所属组和其他用户的读、写、执行。目录的读表示列出名称，写表示增删目录项，执行表示进入和访问其中路径。服务应使用专用低权限用户运行。

### 70. 软链接和硬链接有什么区别？

**回答：** 硬链接是同一个 inode 的另一个目录项，通常不能跨文件系统，也通常不允许指向目录；软链接是保存目标路径的独立文件，可以跨文件系统，但目标删除后会失效。

### 71. 如何排查服务 CPU 很高？

**回答：** 先确认是哪个进程和线程，再结合应用指标、火焰图或采样分析定位热点；同时检查是否有死循环、序列化、正则回溯、GC 或异常重试。不要在没有证据时直接扩容。

### 72. 如何排查内存持续增长？

**回答：** 先区分进程常驻内存、堆、缓存和系统页缓存；观察增长是否最终稳定；获取堆快照或分配剖析，比较对象类型和引用链；检查无界缓存、队列、连接和监听器。修复后用相同流量复测。

### 73. 负载均衡有哪些策略？

**回答：** 常见有轮询、加权轮询、最少连接、随机和一致性哈希。无状态服务容易水平扩展；需要粘性会话时可按 Cookie 或哈希路由，但更推荐把会话放到共享存储，减少实例绑定。

### 74. 健康检查为什么分存活和就绪？

**回答：** 存活检查判断进程是否需要重启；就绪检查判断实例是否可以接收流量。应用启动中、正在优雅关闭或关键依赖不可用时，可以仍然存活但暂时不就绪。

## 七、分布式系统基础

### 75. CAP 定理是什么？

**回答：** 当网络分区发生时，分布式系统无法同时保证强一致性和每个请求都获得成功响应，只能在一致性与可用性之间取舍。CAP 讨论的是分区条件下的选择，不是平时简单地“三选二”。

### 76. 强一致、最终一致分别是什么？

**回答：** 强一致让读操作像访问单一最新副本；最终一致允许副本短时间不同，但没有新写入时最终会收敛。订单支付等关键状态倾向更强的一致性，点赞数和缓存常可接受最终一致。

### 77. 什么是 BASE？

**回答：** BASE 通常指基本可用、软状态和最终一致，是很多分布式系统在高可用和扩展性下采用的思路。它不是放弃一致性，而是让一致性级别匹配业务需求。

### 78. 消息队列有什么作用？

**回答：** 异步解耦、削峰填谷和事件广播。它会引入重复、延迟、积压、顺序和失败处理问题。生产者成功写业务数据却没发出消息时，可用事务消息或 Outbox Pattern 改善一致性。

### 79. 消息为什么可能重复？

**回答：** 消费者处理成功后，在确认消息前崩溃，队列会再次投递。多数系统更现实的语义是至少一次投递，因此消费者必须以业务键实现幂等。所谓“恰好一次”通常只在特定边界和约束内成立。

### 80. Outbox Pattern 是什么？

**回答：** 在同一个数据库事务中同时写业务表和 outbox 事件表，后台发布器再把事件发送到消息系统并记录发布状态。这样避免“数据库提交成功但消息发送失败”的双写不一致，消费者仍需幂等。

### 81. 分布式锁适合解决什么问题？

**回答：** 它用于协调多个进程对共享资源的互斥访问，例如避免同一任务被同时执行。锁需要唯一持有者标识、租约、超时和安全释放；业务正确性还应有唯一约束或版本检查兜底，因为网络分区和暂停可能让旧持有者在租约过期后继续运行。

### 82. 什么是一致性哈希？

**回答：** 把节点和键映射到环上，键落到顺时针最近节点。增加或删除节点时只迁移部分键，适合缓存分片。虚拟节点可以改善数据分布不均。

### 83. 什么是服务降级、限流、熔断？

**回答：** 限流控制进入系统的请求量；熔断在下游持续失败时快速失败；降级在资源不足或依赖故障时关闭非核心能力或返回简化结果。三者共同防止局部故障扩散。

## 八、安全基础

### 84. 对称加密和非对称加密有什么区别？

**回答：** 对称加密使用同一密钥加解密，速度快，适合大量数据；非对称加密使用公私钥，适合密钥交换和数字签名，但计算更贵。TLS 通常用非对称机制完成身份认证和密钥协商，再用对称密钥传输数据。

### 85. 哈希、加密、编码有什么区别？

**回答：** 哈希是单向摘要，用于完整性和索引等；加密使用密钥并可解密，用于保密；编码只改变表示形式，便于传输，不提供安全性。Base64 不是加密。

### 86. 数字签名解决什么问题？

**回答：** 发送方用私钥对消息摘要签名，接收方用公钥验证，从而确认消息未被篡改，并验证签名者持有对应私钥。数字签名通常不负责隐藏消息内容。

### 87. 什么是最小权限原则？

**回答：** 用户、服务和凭证只拥有完成当前任务所需的最少权限，并限制作用范围和有效时间。例如分析服务只读账单表，模型工具不能直接执行任意 SQL，生产密钥不能用于本地开发。

### 88. SSRF 是什么？

**回答：** 攻击者诱导服务端请求其指定地址，从而访问内网、云元数据或其他受保护资源。防护包括目标域名白名单、解析后校验 IP、禁止私网和特殊协议、限制重定向，并隔离出站网络权限。

### 89. 重放攻击是什么？

**回答：** 攻击者截获合法请求后再次发送，以重复执行操作。可以使用 TLS、防重放 nonce、时间戳、短有效期、签名和服务端幂等记录。支付和写接口尤其需要业务唯一号。

## 九、综合场景题

### 90. 一个接口突然变慢，如何排查？

按从现象到依赖的顺序回答：

1. 看错误率、P95/P99、吞吐和变慢时间范围，确认是单接口、单实例还是全局。
2. 用 Trace 拆分网关、应用、数据库、Redis和外部 API 耗时。
3. 检查 CPU、内存、GC、事件循环延迟、线程/连接池和队列。
4. 对慢 SQL 看执行计划和锁等待，对外部服务看超时与重试。
5. 对比最近发布、配置和流量变化。
6. 先限流、降级或回滚止损，再验证根因和修复效果。

### 91. 高并发扣库存怎样避免超卖？

**回答：** 把判断和扣减放在数据库原子条件更新中，例如 `UPDATE ... SET stock = stock - 1 WHERE id = ? AND stock > 0`，根据受影响行数判断成功。还要用业务订单号保证幂等。Redis 预扣可以提高吞吐，但需要处理缓存与数据库一致性、补偿和重复消息。

### 92. 如何设计一个短链接系统？

**回答：** 写入时生成唯一短码并保存短码到长 URL 的映射；读取路径高频且简单，可用 Redis 缓存并回源数据库；短码需要足够空间、避免碰撞和被轻易枚举；对恶意链接做审核、限流和过期。访问统计可异步写消息队列，避免阻塞跳转。

### 93. 如何设计任务执行系统？

**回答：** 任务表保存状态、参数、重试次数、租约和幂等键；生产者创建任务后进入队列；Worker 领取任务并周期续租，成功或失败原子更新状态；超时任务可重新投递；重复执行由业务幂等兜底。监控队列积压、执行延迟、失败率和死信。

### 94. 浏览器重复提交表单怎么办？

**回答：** 前端提交中禁用按钮只能改善体验，不能作为正确性保证。服务端为业务操作使用幂等键或唯一业务号，并以数据库唯一约束兜底；重复请求返回第一次的处理结果。

### 95. 缓存与数据库不一致怎么办？

**回答：** 先定义业务允许的不一致窗口。常用 Cache Aside 在数据库提交后删除缓存，并为缓存设置 TTL；删除失败要重试或通过消息处理。强一致场景直接读数据库或使用更严格的同步方案，不应承诺缓存天然强一致。

## 十、面试速记

### 复杂度

- 数组随机访问 `O(1)`，中间插入删除 `O(n)`。
- 哈希表平均查询 `O(1)`，最坏可退化。
- 平衡搜索树操作 `O(log n)`。
- 堆顶 `O(1)`，插入和删除堆顶 `O(log n)`。
- BFS/DFS 为 `O(V + E)`。
- 比较排序下界为 `O(n log n)`。

### 网络

- TCP：可靠、有序、字节流；UDP：无连接、保留报文边界。
- 三次握手同步双方能力和序列号；四次挥手来自双向独立关闭。
- HTTP/2 多路复用仍受 TCP 丢包影响；HTTP/3 基于 QUIC。
- HTTPS = HTTP over TLS；Base64 不是加密。
- SSE 适合单向推送，WebSocket 适合全双工。

### 操作系统

- 进程重隔离，线程重执行，协程重用户态调度。
- 异步提升 I/O 并发，不能自动加速 CPU 计算。
- 死锁四条件：互斥、占有且等待、不可剥夺、循环等待。
- 虚拟内存通过页表映射物理内存，TLB 缓存地址转换。
- `epoll` 适合大量连接、少量活跃的事件驱动服务。

### 数据库与分布式

- 索引加速读，但增加存储和写成本。
- MVCC 让读操作访问合适版本，减少读写阻塞。
- 乐观锁靠版本检查，悲观锁先锁后改。
- 消息系统通常按至少一次投递设计，消费者必须幂等。
- CAP 是网络分区发生时一致性与可用性的取舍。

真正面试时，定义只占前 20 秒。后面的得分来自你能否说清边界、反例和项目中的实际选择。
