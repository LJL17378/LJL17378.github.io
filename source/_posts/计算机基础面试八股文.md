这份手册按全栈和大前端面试的实际使用频率组织。它不是只有关键词的题目清单，而是把常见题库中的高频问题整理成可以直接复述、也经得住继续追问的答案。

学习时不要逐句硬背。每个概念都按四步理解：

1. **它为什么出现：** 没有它时会遇到什么问题？
2. **它怎样工作：** 数据或控制流到底经过了什么步骤？
3. **它牺牲了什么：** 时间、空间、一致性还是实现复杂度？
4. **它在哪里出现：** 浏览器、Python 服务、MySQL 或 Redis 中是否见过？

回答时也尽量沿着这四步展开。只记住“AVL 是平衡树”很容易忘；理解“普通搜索树可能退化成链表，AVL 用旋转把高度拉回对数级”，知识才会连起来。

## 一、数据结构与算法

### 先建立“数据怎样被组织”的地图

数据结构是在为某些操作付费：数组用连续内存换来快速随机访问；链表牺牲随机访问换取局部插入；哈希表用额外空间换等值查询；平衡树维护顺序并保证最坏复杂度；堆只保证堆顶最优，因此适合优先队列；图则表达任意关系。

算法题不要从代码模板开始。先问输入规模和目标操作，再选结构。例如需要不断加入数字并查询最大值，不必维护完整排序，堆顶已经足够；需要区间扫描，就不能只依赖哈希表。选择的关键是“题目真正需要哪些操作”。

树结构可以按使用场景记忆：AVL/红黑树主要优化内存中的动态有序集合；B/B+ 树降低页式存储的访问层数；Trie 利用字符串前缀；堆只关心局部最值。它们并不是彼此替代的同一种树。

### 1. 如何分析时间复杂度和空间复杂度？

**回答：** 时间复杂度描述输入规模增长时，操作次数的增长量级；空间复杂度描述额外内存的增长量级。分析时保留最高阶项并忽略常数，例如两层各执行 n 次的循环是 `O(n²)`。需要区分最坏、平均和均摊复杂度。

不要把 `O(n)` 理解成“恰好执行 n 次”，它描述的是增长趋势。`3n + 100` 和 `n` 在 n 足够大时增长速度相同，所以都记为 `O(n)`；二分查找每次把范围减半，最多减半约 `log₂n` 次，所以是 `O(log n)`。

**记忆：** 顺着代码看循环，顺着递归看问题规模，看到“每次减半”先想到对数，看到“所有节点和所有边各处理一次”先想到 `O(V+E)`。

### 2. 什么是均摊复杂度？

**回答：** 某次操作可能很贵，但在一长串操作中平均成本较低。例如动态数组扩容一次需要复制 `O(n)` 个元素，但按倍数扩容后，多次尾部追加的均摊复杂度仍是 `O(1)`。

假设容量按 2 倍增长，插入 8 个元素时，大约在容量 1、2、4 时分别复制 1、2、4 个元素，总复制次数小于后续元素数量的常数倍。昂贵扩容不会每次发生，因此把总成本摊到每次追加上仍是常数级。均摊是对一串操作的数学保证，不等于某一次操作绝对很快。

### 3. 数组和链表有什么区别？

**回答：** 数组内存连续，支持 `O(1)` 随机访问，缓存局部性好；中间插入删除通常需要移动元素。链表节点分散，定位第 k 个元素是 `O(n)`，已知节点位置时插入删除可为 `O(1)`，但指针占空间且缓存不友好。

“链表插入是 `O(1)`”有一个经常被省略的前提：**已经拿到插入位置的节点**。如果先按下标走到第 k 个节点，定位本身仍要 `O(n)`。工程中数组往往比理论分析看起来更快，因为 CPU 能连续预取相邻元素，而链表会频繁跳转内存地址。

### 4. 栈和队列分别适合什么场景？

**回答：** 栈后进先出，适合函数调用、括号匹配、撤销和 DFS；队列先进先出，适合任务调度、消息缓冲和 BFS。双端队列允许两端插入删除，可用于单调队列和滑动窗口。

可以用生活场景记忆：栈像一摞盘子，最后放上去的先拿；队列像排队购票，先来先服务。浏览器返回历史、函数调用栈体现 LIFO；消息消费者和广度优先搜索体现 FIFO。选错结构会直接改变处理顺序，而不只是性能不同。

### 5. 哈希表为什么平均是 O(1)？

**回答：** 哈希函数把键映射到桶，可直接定位候选位置，所以平均查找接近常数。发生哈希冲突时可用链地址法或开放寻址法解决；冲突过多或装载因子过高会退化，因此需要扩容和良好哈希函数。

例如用用户 ID 查资料时，哈希函数把 ID 计算成数组下标，程序不必从头遍历所有用户。但两个不同 ID 可能落入同一个桶，这就是冲突。所谓平均 `O(1)` 依赖键分布较均匀、容量充足和冲突得到控制；极端情况下同一个桶形成长链，仍可能退化到 `O(n)`。

### 6. 哈希表和有序树如何选择？

**回答：** 只需要等值查询时哈希表通常更快；需要有序遍历、范围查询、前驱后继或稳定的 `O(log n)` 上界时，使用平衡搜索树。数据库索引还要考虑磁盘页，因此常使用 B+ 树。

例如“根据 session ID 找会话”主要是等值查询，哈希表很合适；“找出 100 到 200 元之间的账单，并按金额遍历”需要顺序关系，平衡树更自然。记住一句话：**哈希回答‘它在不在’，有序树还能回答‘它前后是谁、某个范围有哪些’。**

### 7. 二叉搜索树为什么会退化？

**回答：** 如果输入接近有序，普通二叉搜索树可能变成链表，查找从 `O(log n)` 退化到 `O(n)`。AVL 树和红黑树通过旋转保持高度近似对数级。AVL 更严格平衡、查询稳定；红黑树调整通常更少，常用于通用有序容器。

### 8. 堆是什么？

**回答：** 堆通常是完全二叉树，最大堆保证父节点不小于子节点，最小堆相反。查看堆顶是 `O(1)`，插入和删除堆顶是 `O(log n)`。常用于优先队列、Top K、定时任务和堆排序。

堆只保证父子之间的偏序，不保证整棵树完全有序。因此最小堆能立刻告诉你最小元素，却不能像有序数组一样直接得到第二小、第三小。它适合“反复取当前最优”，不适合任意范围查询。

### 9. BFS 和 DFS 有什么区别？

**回答：** BFS 按层扩展，通常使用队列，在无权图中能找到最短边数路径；DFS 沿一条路径深入，通常使用递归或栈，适合连通性、回溯、拓扑和枚举。二者时间通常都是 `O(V + E)`，空间取决于图结构和搜索前沿。

把 BFS 想成水面一圈圈扩散，所以第一次到达目标时经过的边数最少；把 DFS 想成走迷宫时沿一条路走到底，不通就退回岔路口。BFS 的队列可能保存很宽的一整层，DFS 的递归栈可能因路径很深而溢出，选择时还要看图的宽度和深度。

### 10. 什么是拓扑排序？

**回答：** 对有向无环图给出一个线性顺序，使每条边的起点都在终点之前。可用入度法：把入度为 0 的节点入队，依次删除它的出边；如果最终处理节点数少于总节点数，说明存在环。它适合任务依赖和构建顺序。

### 11. 常见排序算法如何比较？

| 算法 | 平均时间 | 最坏时间 | 额外空间 | 稳定性 |
| --- | --- | --- | --- | --- |
| 快速排序 | `O(n log n)` | `O(n²)` | 平均 `O(log n)` | 不稳定 |
| 归并排序 | `O(n log n)` | `O(n log n)` | `O(n)` | 稳定 |
| 堆排序 | `O(n log n)` | `O(n log n)` | `O(1)` | 不稳定 |
| 插入排序 | `O(n²)` | `O(n²)` | `O(1)` | 稳定 |

工程中的排序通常是混合算法，会针对小数组、近似有序输入和最坏情况做优化。

### 12. 快排为什么通常很快？

**回答：** 平均复杂度是 `O(n log n)`，原地分区且缓存局部性好，常数较小。选择随机枢轴或三数取中可以降低极端输入导致退化的概率。若必须保证最坏复杂度，可使用堆排序或内省排序。

### 13. 二分查找的关键是什么？

**回答：** 关键不是背模板，而是明确搜索区间定义和循环不变量。例如左闭右闭使用 `left <= right`，更新时排除 `mid`；寻找第一个满足条件的位置时，可把问题转换为单调布尔序列的边界查找。

### 14. 常见算法题型应掌握哪些模式？

- 哈希：两数之和、频次统计、去重。
- 双指针：有序数组、区间收缩、链表快慢指针。
- 滑动窗口：连续子数组或子串。
- 前缀和：快速求区间和。
- 单调栈：下一个更大元素、柱状图。
- 回溯：排列、组合、子集。
- 动态规划：状态、转移、初值和遍历顺序。
- 图：BFS、DFS、并查集、拓扑排序、最短路。

### 15. 动态规划与贪心有什么区别？

**回答：** 动态规划保存重叠子问题的最优结果，通过状态转移获得全局最优；贪心每一步选当前看起来最优的选择，只有满足贪心选择性质时才正确。无法证明局部最优能推出全局最优时，不应凭感觉使用贪心。

零钱兑换是很好的反例：硬币为 `1、3、4`，凑 6 元时每次拿最大硬币会得到 `4+1+1`，需要 3 枚；全局最优是 `3+3`，只需 2 枚。贪心代码往往更简单，但必须能证明交换任意最优解后仍可包含当前选择；不能证明时，优先考虑动态规划或搜索。

### 16. LRU 缓存如何实现？

**回答：** 哈希表负责 `O(1)` 定位节点，双向链表维护最近使用顺序。访问或更新节点时移到链表头，容量满时删除尾部节点，并同步删除哈希表记录。两种结构必须保持一致。

为什么需要两种结构？只有链表时，能快速淘汰尾部，却要线性查找某个 Key；只有哈希表时，能快速找到 Key，却不知道谁最久没用。组合后一次 `get` 的过程是：哈希定位节点 → 从原位置摘下 → 移到链表头。面试实现最容易漏掉的是更新已有 Key、容量为零，以及删除节点后同步更新哈希表。

### 17. AVL 树是什么？为什么需要旋转？

**回答：** AVL 是一种严格平衡的二叉搜索树，任意节点左右子树高度差的绝对值不超过 1。插入或删除破坏平衡后，通过旋转恢复，同时保持中序遍历顺序不变。LL、RR 使用一次旋转，LR、RL 使用两次旋转。查找、插入、删除最坏均为 `O(log n)`，代价是每个节点要维护高度或平衡因子，并且更新时可能做更多调整。

例如依次插入 `30、20、10`，树会向左形成一条链，这是 LL 情况。以 30 为中心做一次右旋后，20 成为根，10 和 30 分居左右，搜索树的大小关系没有改变，高度却从 3 降为 2。记忆四种情况时先看“失衡节点到新节点”的方向：同向 LL/RR 单旋，拐弯 LR/RL 双旋。

### 18. AVL 树和红黑树有什么区别？

**回答：** 两者都保证树高为 `O(log n)`。AVL 平衡更严格，通常树更矮，适合查询明显多于更新的场景；红黑树用颜色规则保证“近似平衡”，插入删除所需的旋转通常更少，更适合频繁更新的通用有序容器。面试时不要说红黑树一定比 AVL 快，实际表现还取决于数据分布、实现和读写比例。

### 19. 红黑树需要满足哪些性质？

**回答：** 节点为红或黑；根通常为黑；空叶子视为黑；红节点不能有红孩子；从任意节点到所有后代空叶子的路径包含相同数量的黑节点。由此最长路径不会超过最短路径的两倍，树高保持 `O(log n)`。插入删除后通过变色和旋转修复性质。

### 20. B 树、B+ 树与二叉搜索树有什么区别？

**回答：** B 树和 B+ 树是多路平衡搜索树，一个节点可以存多个键和多个孩子，因此树高远小于二叉树，更适合磁盘或页式存储。B 树的内部节点和叶子都可保存记录；B+ 树通常只在叶子保存完整记录，内部节点只做导航，叶子再按顺序相连。B+ 树单个页能容纳更多索引项，范围扫描也更方便。

可以把二叉树想成每页目录只能指向两页，数据多时要翻很多层；B+ 树的一页能保存大量键和子页指针，可能三四层就管理数百万行。内部节点不保存完整记录后，同样大小的页能放更多导航键，树也更矮。叶子链表让 `WHERE amount BETWEEN 100 AND 200` 定位起点后可以顺序向后扫描。

### 21. 为什么数据库索引常用 B+ 树，而不是 AVL 树或哈希表？

**回答：** 数据库访问成本主要来自页 I/O。B+ 树分支多、树高低，一次查询通常只需访问少量页；叶子有序连接，适合范围、排序和前缀扫描。AVL 是二叉树，数据量大时层数和随机页访问更多。哈希索引擅长等值查询，但不天然支持范围和有序遍历。具体数据库可能把结构统称为 B-tree，实现细节应以存储引擎为准。

**记忆：** 内存结构常关心比较次数，数据库结构更关心“要读几页”。这就是 B+ 树与 AVL 的关键分界。

### 22. Trie 前缀树适合什么场景？

**回答：** Trie 按字符或比特逐层保存键，查找复杂度主要取决于键长，而不是键的数量。它适合前缀搜索、自动补全、词典和路由匹配。缺点是节点和指针多，空间开销可能很大，可通过压缩 Trie、基数树或紧凑数组降低开销。

### 23. 并查集解决什么问题？

**回答：** 并查集维护若干互不相交的集合，核心操作是查询两个元素是否同属一个集合，以及合并两个集合。使用路径压缩和按秩或按大小合并后，单次操作的均摊复杂度接近 `O(1)`。常用于连通分量、冗余边、账户合并和 Kruskal 最小生成树。

### 24. 布隆过滤器是什么？有什么误判？

**回答：** 布隆过滤器用位数组和多个哈希函数判断元素是否可能存在。返回“不存在”时一定不存在；返回“可能存在”时可能是假阳性。它空间效率高，适合在访问数据库前拦截明显不存在的键。普通布隆过滤器不便删除，容量和误判率需要提前估算，也不能把它当成最终权限或一致性判断。

### 25. 跳表是什么？为什么 Redis 有序集合会使用它？

**回答：** 跳表在有序链表上增加多级稀疏索引，以随机层高换取期望 `O(log n)` 的查找、插入和删除。它实现相对直观，范围遍历天然顺序进行。与平衡树相比，跳表依赖随机化且空间更多，但并发和工程实现通常更简单。具体 Redis 结构还会配合哈希表实现按成员快速定位。

### 26. 如何用堆解决 Top K 问题？

**回答：** 求最大的 K 个元素时维护大小为 K 的最小堆：前 K 个入堆，之后只有元素大于堆顶才替换堆顶。时间复杂度是 `O(n log k)`，额外空间 `O(k)`。如果数据范围小、K 接近 n，排序、快速选择或计数方法可能更合适。

### 27. 建堆为什么可以是 O(n)？

**回答：** 从最后一个非叶子节点向上做下沉时，大多数节点都靠近叶子，只需移动很短距离。把每一层的节点数乘以下沉高度后求和，得到线性级别，因此自底向上建堆是 `O(n)`；逐个插入 n 个元素则是 `O(n log n)`。

### 28. 图的邻接矩阵和邻接表如何选择？

**回答：** 邻接矩阵占 `O(V²)` 空间，判断两点是否相邻是 `O(1)`，适合稠密图；邻接表占 `O(V+E)`，遍历某点邻边高效，适合稀疏图。实际还要考虑边权、多重边、删除操作和缓存局部性。

### 29. Dijkstra、Bellman-Ford 和 Floyd 有什么区别？

**回答：** Dijkstra 求单源最短路，要求边权非负，配合优先队列常为 `O((V+E) log V)`；Bellman-Ford 可处理负权边并检测可达负环，复杂度 `O(VE)`；Floyd-Warshall 用动态规划求任意两点最短路，复杂度 `O(V³)`，适合节点较少的稠密图。

### 30. 最小生成树中的 Kruskal 和 Prim 如何选择？

**回答：** Kruskal 按边权排序，依次加入不会成环的边，通常用并查集判环，适合稀疏图；Prim 从一个点向外扩展当前最小跨边，配合优先队列适合邻接表表示。两者解决的是连通无向带权图的最小生成树，不是两点最短路径。

### 31. 如何判断链表或图中是否存在环？

**回答：** 单链表可用快慢指针：快指针每次走两步，若与慢指针相遇则有环，再通过数学关系找到入口。无向图 DFS 时记录父节点；有向图可用三色标记或拓扑排序，访问到当前递归栈中的节点说明存在环。并查集也能检测无向图逐边加入时是否成环。

### 32. 什么是稳定排序？什么时候重要？

**回答：** 稳定排序会保持相等键元素的原相对顺序。对数据先按次要字段排序、再稳定地按主要字段排序时，稳定性可以保留次要顺序；展示列表、多级排序也常依赖它。归并和插入排序通常稳定，堆排序和常规原地快排通常不稳定。

### 33. KMP 字符串匹配解决了什么问题？

**回答：** 暴力匹配失败后可能重复比较已经匹配的字符。KMP 预处理模式串的最长相等真前后缀信息，失配时直接移动模式串而不回退文本指针，总复杂度为 `O(n+m)`。关键是理解前缀函数或 `next` 数组表示“当前已匹配前缀还能复用多少”。

### 34. 回溯和动态规划有什么关系？

**回答：** 回溯枚举决策树并撤销选择，适合输出所有方案或约束组合；剪枝用约束提前停止无效分支。若不同路径反复到达同一状态，可用记忆化搜索减少重复计算，进一步整理成动态规划。两者都依赖状态设计，但回溯关注搜索空间，动态规划关注可复用子问题。

## 二、操作系统

### 操作系统是在有限硬件上制造三个“假象”

第一，多个程序看起来都在同时使用 CPU，背后是调度和上下文切换；第二，每个进程看起来拥有独立而连续的内存，背后是虚拟地址、页表和页面置换；第三，程序看起来在操作稳定的文件，背后是文件系统、缓存、设备和崩溃恢复。

并发问题来自这些抽象被多个执行流同时使用。锁、信号量和条件变量不是要背的 API，而是在回答三个不同问题：谁能进入临界区、还有多少资源、条件不满足时怎样等待。理解问题后再记工具，混淆会少很多。

### 35. 进程、线程和协程有什么区别？

**回答：** 进程是资源分配和隔离单位，拥有独立虚拟地址空间；线程是 CPU 调度的基本执行单位，同一进程内共享内存和文件等资源；协程是用户态的协作式任务，由运行时在明确的挂起点切换，切换成本通常更低。

可以把它们理解为“房子、房间里的人和一个人手上的待办事项”：不同进程像独立房子，隔离强，通信成本也高；同一进程的线程共享房内资源，所以交流快，但一个线程破坏共享内存可能影响整个进程；协程由运行时在等待点切换，数量可以很多，但阻塞事件循环仍会一起卡住。

**选型：** 强隔离或 CPU 并行考虑多进程；共享数据且依赖阻塞库可考虑线程；大量异步 I/O 适合协程。三者可以组合使用。

### 36. 进程间如何通信？

**回答：** 常见方式有管道、消息队列、共享内存、信号、Socket 和文件。共享内存吞吐高，但需要同步；Socket 可跨机器，通用但协议和拷贝成本更高。选择取决于数据量、可靠性、通信范围和复杂度。

### 37. 线程共享什么，不共享什么？

**回答：** 同一进程的线程共享代码段、堆、全局数据和打开的文件；每个线程有自己的栈、寄存器、程序计数器和线程局部存储。共享内存带来通信便利，也带来数据竞争。

为什么栈不能共享？因为每个线程都需要独立记录自己调用到哪个函数、局部变量是什么、返回到哪里。如果调用栈也混在一起，线程切换后就无法恢复执行现场。为什么堆会产生竞态？因为两个线程可能同时读取旧值并写回新值，使一次更新被覆盖。

### 38. 什么是上下文切换？

**回答：** CPU 从一个任务切换到另一个任务时，需要保存和恢复寄存器、程序计数器等状态，还可能影响 CPU 缓存和 TLB。线程或进程过多会增加切换成本，因此并发数并非越大越好。

### 39. 并发和并行有什么区别？

**回答：** 并发是多个任务在一段时间内交替推进；并行是多个任务在同一时刻真正同时执行。单核也可以并发，多核才能让多个 CPU 任务并行。异步主要改善等待型任务的并发，不直接增加 CPU 算力。

一个厨师交替照看三口锅是并发，三个厨师同时炒三道菜是并行。并发关注任务怎样被组织和推进，并行关注同一时刻是否真的有多个执行单元。Node.js 和 asyncio 能高效并发处理等待型请求，却不会让同一段 CPU 计算自动在多个核心并行。

### 40. 什么是竞态条件？

**回答：** 多个执行单元并发访问共享状态，结果依赖不可预测的执行顺序，就产生竞态。解决方法包括互斥锁、原子操作、消息传递、不可变数据和减少共享状态。锁只保护共同约定的临界区，遗漏任何访问仍会出错。

### 41. 互斥锁、读写锁、信号量和条件变量有什么区别？

- 互斥锁：同一时刻只允许一个执行者进入临界区。
- 读写锁：允许多个读者或一个写者，适合读多写少。
- 信号量：维护许可数量，可限制并发资源数。
- 条件变量：让线程等待某个条件成立，通常与互斥锁配合。

用停车场来记：互斥锁像只有一个车位的独占区域；信号量像有 N 个车位的停车场；读写锁像展览室，参观者可以多人同时进入，但布展人员进入时必须清场；条件变量像“有空位再叫我”，等待者先释放锁睡眠，被通知后重新拿锁并再次检查条件。

条件变量必须配合循环检查，而不是收到一次通知就假设条件成立，因为可能出现虚假唤醒，或者条件已经被另一个线程抢先改变。

### 42. 死锁的四个必要条件是什么？

**回答：** 互斥、占有且等待、不可剥夺、循环等待。破坏任一条件可预防死锁，例如统一锁顺序破坏循环等待，或一次申请全部资源减少占有且等待。

最经典的场景是线程 A 拿着锁 1 等锁 2，线程 B 拿着锁 2 等锁 1，双方都不会主动释放。工程上通常通过固定加锁顺序、缩短事务与临界区、设置超时，以及死锁检测后的重试处理，而不是试图完全证明系统永远无死锁。

### 43. 用户态和内核态是什么？

**回答：** 用户态权限受限，普通应用运行在其中；内核态可访问硬件和关键内存。应用通过系统调用请求文件、网络和进程管理等内核服务。用户态与内核态切换有成本，但与进程上下文切换不是同一个概念。

### 44. 什么是虚拟内存？

**回答：** 每个进程看到独立、连续的虚拟地址空间，操作系统通过页表映射到物理内存。它提供进程隔离、地址空间抽象、按需加载和共享页面，也允许暂时把不活跃页面换出到磁盘。

程序使用的是虚拟地址，CPU 和操作系统借助页表把它翻译成物理页。两个进程都可以使用看起来相同的地址，但映射到不同物理内存，因此互不干扰；它们也可以把某些虚拟页映射到同一物理页，实现共享库或共享内存。

**记忆：** 虚拟内存的重点不只是“内存不够时用磁盘”，更重要的是隔离、统一地址视图和按需映射。

### 45. 什么是缺页中断？

**回答：** CPU 访问的虚拟页当前没有有效物理映射时触发异常，操作系统判断访问是否合法；若合法，则从磁盘加载或分配页面，更新页表后重新执行指令。若内存不足，可能需要置换其他页面。大量缺页会造成抖动。

### 46. 什么是 TLB？

**回答：** TLB 是页表映射的高速缓存，避免每次地址转换都多次访问内存。上下文切换和大工作集可能降低 TLB 命中率；大页可以减少页表项数量，但会增加内部碎片和管理取舍。

### 47. 堆和栈有什么区别？

**回答：** 栈通常保存函数调用帧和局部变量，由调用约定自动管理，分配快但空间有限；堆用于动态分配、生命周期灵活，由分配器和程序或垃圾回收器管理，可能产生碎片。这里的“堆”内存区域与“堆”数据结构不是一个概念。

### 48. 什么是 I/O 多路复用？

**回答：** 一个线程可以等待多个文件描述符的就绪事件，而不为每个连接创建一个阻塞线程。Linux 常见机制有 `select`、`poll` 和 `epoll`。`epoll` 通过内核维护关注集合和就绪列表，适合大量连接中只有少量活跃的场景。

可以把它想成前台同时等待很多房间的呼叫铃：前台不必派一个人守在每个房间门口，而是让系统告诉它“哪些房间现在有事”，再逐个处理。多路复用通知的是“可以读写了”，业务代码仍需要真正执行读取、解析和响应；如果处理回调本身很慢，同一个事件循环仍会被堵住。

### 49. select、poll、epoll 有什么区别？

**回答：** `select` 的描述符数量和表示方式受限制，每次调用需传递并扫描集合；`poll` 取消固定数量限制，但仍线性扫描；`epoll` 注册关注事件后获取就绪列表，避免每次扫描全部连接。实际性能还取决于连接活跃度和应用模型。

### 50. 什么是零拷贝？

**回答：** 零拷贝不是完全没有任何复制，而是减少数据在用户态和内核态之间的无谓复制及上下文切换。例如 `sendfile` 可让文件数据从页缓存直接进入 Socket 发送路径，适合静态文件传输。

### 51. 阻塞、非阻塞、同步、异步如何区分？

**回答：** 阻塞/非阻塞描述调用在结果未就绪时是否立即返回；同步/异步描述结果由调用方主动等待，还是完成后通过回调、事件等方式通知。四个概念经常组合出现，不能简单把非阻塞等同于异步。

### 52. 进程有哪些常见状态？

**回答：** 常见模型包含新建、就绪、运行、阻塞或等待、终止。运行中的任务等待 I/O 会进入阻塞，I/O 完成后回到就绪；时间片用完或被更高优先级任务抢占也会回到就绪。就绪表示只缺 CPU，阻塞表示还在等待某个事件。

### 53. 常见 CPU 调度算法有哪些？

**回答：** FCFS 简单但可能产生护航效应；SJF 或最短剩余时间能降低平均等待时间，但需要预测任务长度且可能饿死长任务；时间片轮转强调响应性；优先级调度可能造成饥饿，可用老化缓解；多级反馈队列根据任务行为动态调整优先级，兼顾交互任务和长任务。

### 54. `fork`、`exec` 和 `wait` 分别做什么？

**回答：** Unix 中 `fork` 创建当前进程的子进程，通常借助写时复制避免立刻拷贝全部内存；`exec` 用新程序替换当前进程映像；父进程用 `wait` 或 `waitpid` 回收子进程退出状态。Shell 启动命令通常组合使用这三个机制。

### 55. 僵尸进程和孤儿进程是什么？

**回答：** 子进程已退出但父进程尚未读取退出状态时，会留下只保存少量状态的僵尸进程；大量僵尸会耗尽进程表项。父进程先退出后，仍在运行的子进程成为孤儿进程，会被系统中的收养者接管并最终回收。服务应正确处理 `SIGCHLD` 或调用等待接口。

### 56. 分页和分段有什么区别？

**回答：** 分页把虚拟和物理空间切成固定大小的页，便于离散分配，消除外部碎片但可能产生页内碎片；分段按代码、数据、栈等逻辑单元划分，边界和权限更贴近程序语义，但会产生外部碎片。现代系统通常以分页为主。

### 57. 常见页面置换算法有哪些？

**回答：** OPT 淘汰未来最久不用的页，只能作为理论最优基准；FIFO 淘汰最早进入的页，简单但可能出现分配更多页反而缺页更多的 Belady 异常；LRU 淘汰最久未访问页，效果好但精确实现成本高；Clock 用访问位近似 LRU，工程上更实用。

### 58. 什么是写时复制（Copy-on-Write）？

**回答：** 多个执行主体先共享同一份只读物理页，只有某一方写入时才复制该页。它让 `fork`、不可变快照等操作避免无意义的立即复制。代价是首次写入会触发缺页和复制，写密集场景收益会降低。

### 59. 自旋锁和互斥锁如何选择？

**回答：** 自旋锁拿不到锁时持续占用 CPU 重试，适合临界区极短、竞争低且不能睡眠的场景；互斥锁竞争时让线程阻塞，节省 CPU，但涉及调度和上下文切换。等待时间不可控或临界区包含 I/O 时不应长时间自旋。

### 60. CAS 是什么？ABA 问题是什么？

**回答：** CAS 比较内存值是否仍等于预期值，若相等则原子更新，是很多无锁算法的基础。ABA 指值从 A 变成 B 又变回 A，CAS 只看当前值会误以为没有变化。可用版本号、带标记指针或合适的内存回收方案解决。

### 61. 什么是 CPU 缓存一致性和伪共享？

**回答：** 多核 CPU 通过缓存一致性协议协调共享内存。两个线程即使修改不同变量，如果变量落在同一缓存行，也会反复使对方缓存行失效，这叫伪共享。可通过数据分片、对齐或填充减少，但要用性能数据验证。

### 62. `mmap` 有什么用途？

**回答：** `mmap` 把文件或匿名内存映射到进程虚拟地址空间，程序可像访问内存一样访问文件页。它适合随机访问、大文件、进程共享内存和按需加载。它不代表完全没有拷贝，缺页、回写、同步和文件截断等边界仍需处理。

### 63. 文件系统中的 inode 和目录项是什么？

**回答：** inode 保存文件类型、权限、大小、时间和数据块位置等元数据，文件名通常保存在目录项中并映射到 inode。硬链接是多个目录项指向同一个 inode；删除一个文件名只是减少链接计数，计数为零且没有进程打开后空间才可回收。

### 64. 文件系统为什么需要日志（Journaling）？

**回答：** 更新文件通常涉及多个元数据和数据块，断电可能只完成一部分。日志文件系统先记录将要执行的关键更新，再应用到主结构，崩溃后通过重放或回滚恢复一致状态。不同日志模式对数据内容和元数据的保护范围、性能也不同。

### 65. 容器和虚拟机有什么区别？

**回答：** 虚拟机通过虚拟化硬件运行独立客体内核，隔离强但启动和资源开销较大；容器共享宿主内核，使用 namespace 做视图隔离、cgroup 做资源限制，镜像和启动更轻。共享内核意味着安全边界和兼容性需要额外评估。

## 三、计算机网络

### 网络题沿着“一份数据怎样到达另一个进程”来学

应用先生成 HTTP 消息，传输层把它变成可传输的数据流或报文，网络层负责跨网段寻址，链路层负责当前一跳交付。DNS 先帮你找到地址，TCP 或 QUIC 建立传输关系，TLS 建立加密与身份信任，HTTP 再表达具体业务。

出现故障时也沿这条链路反查：域名能否解析、地址能否路由、端口能否连接、TLS 是否通过、HTTP 返回什么状态、应用是否及时响应。这样比孤立背七层模型更容易用于实际排障。

### 66. OSI 七层和 TCP/IP 模型如何对应？

**回答：** OSI 包含物理、数据链路、网络、传输、会话、表示、应用七层。实际互联网常用 TCP/IP 分层：链路层、网际层、传输层、应用层。HTTP 位于应用层，TCP/UDP 位于传输层，IP 位于网际层，以太网/Wi-Fi 位于链路层。

### 67. 从输入 URL 到页面显示发生了什么？

**回答：** 浏览器解析 URL，检查缓存和相关策略；通过 DNS 获取地址；建立传输连接，HTTPS 还要进行 TLS 握手；发送 HTTP 请求；经过 CDN、代理和服务端处理后返回响应；浏览器解析 HTML，获取 CSS、JS 和图片，构建 DOM/CSSOM、布局、绘制与合成，并执行脚本和框架渲染。

面试中应根据追问展开，不要一开始把所有细节一次背完。

### 68. TCP 和 UDP 有什么区别？

**回答：** TCP 面向连接，提供可靠、有序的字节流，并实现流量控制和拥塞控制；UDP 无连接，保留报文边界，不保证到达和顺序，头部与状态更少。实时音视频、DNS 等可基于 UDP 自己实现需要的可靠性；HTTP/3 的 QUIC 也构建在 UDP 上。

### 69. TCP 为什么需要三次握手？

**回答：** 三次握手让双方确认彼此的发送和接收能力，并同步初始序列号。两次不足以让服务端确认客户端收到了自己的初始序列号，也更难避免旧连接请求造成错误状态。

过程可以记成：客户端说“我想从序号 x 开始发”；服务端回答“我听到了，你从 x 开始；我想从 y 开始”；客户端再确认“我也听到了 y”。第三次不是形式主义，它让服务端知道自己的响应确实到达客户端，双方才拥有一致的连接状态。

### 70. TCP 为什么通常四次挥手？

**回答：** TCP 是全双工，关闭一个方向和关闭另一个方向可以分开发生。收到 FIN 只代表对方不再发送，本方可能仍有数据要发，所以 ACK 和本方 FIN 通常分开。若恰好没有剩余数据，也可能合并发送。

### 71. TIME_WAIT 有什么作用？

**回答：** 主动关闭方等待两倍最大报文生存时间，一是确保最后的 ACK 丢失时还能重发，二是让旧连接的延迟报文从网络中消失，避免污染相同四元组的新连接。大量 TIME_WAIT 需要从连接复用、短连接数量和端口范围等方面分析。

假设主动关闭方发出的最后 ACK 丢了，对方会再次发送 FIN；处于 TIME_WAIT 的一方还能重新确认。如果它立刻消失并复用相同连接四元组，旧连接中迟到的数据也可能被误认为新连接的数据。因此 TIME_WAIT 是可靠关闭的一部分，不应看到数量多就直接粗暴关闭。

### 72. TCP 如何保证可靠传输？

**回答：** 通过序列号、确认应答、校验、超时重传、快速重传、滑动窗口和乱序重组。可靠不代表永不失败，应用仍需处理连接中断和不确定结果。

把一段数据想成编号包裹：序列号标记每个字节位置，ACK 告诉发送方“我已经连续收到哪里”，校验和发现传输损坏，超时或重复 ACK 触发重发，接收端再按序号重组乱序数据。TCP 保证的是连接存续期间交付给应用的字节流可靠有序；连接断开后，一次业务操作是否已经生效仍要由应用查询或通过幂等处理。

### 73. 流量控制和拥塞控制有什么区别？

**回答：** 流量控制保护接收方，接收窗口表示还能接收多少数据；拥塞控制保护网络，根据丢包、延迟等信号调整发送速率。实际发送窗口受两者共同限制。

可以记成两个瓶颈：接收方说“我的仓库还放得下多少”，这是流量控制；网络说“路上现在有多堵”，这是拥塞控制。即使接收方内存很大，网络拥塞时也不能全速发送；即使网络畅通，接收缓冲区快满时也必须减速。

### 74. TCP 粘包是什么？

**回答：** TCP 是字节流，没有消息边界。发送方多次写入的数据，接收方可能一次读到，也可能拆成多次读到。应用协议必须自行划分消息，可用固定长度、分隔符、长度前缀或自描述格式。UDP 保留报文边界。

### 75. HTTP/1.1、HTTP/2 和 HTTP/3 有什么区别？

**回答：** HTTP/1.1 支持持久连接，但同一连接上的请求处理能力有限，浏览器常开多个连接。HTTP/2 使用二进制分帧和多路复用，并压缩头部，但多个流共享一个 TCP 连接，丢包可能造成传输层队头阻塞。HTTP/3 基于 QUIC，为流提供更独立的传输，并改善握手和连接迁移。

演进主线可以记成：**复用连接 → 复用连接中的多条流 → 让多条流在传输层也更独立。** HTTP/2 解决了应用层按顺序等待的问题，但底层 TCP 丢掉一个报文时，后续字节仍要等它重传；QUIC 在用户态管理独立流，一个流丢包不必阻塞其他流的数据交付。

### 76. HTTP 常见缓存头有哪些？

**回答：** `Cache-Control: max-age` 控制新鲜时间；`no-cache` 表示使用前需要重新验证，并非完全不缓存；`no-store` 表示不应存储；`ETag/If-None-Match` 和 `Last-Modified/If-Modified-Since` 用于协商缓存，未变化可返回 `304`。

### 77. Cookie、Session、Token 有什么区别？

**回答：** Cookie 是浏览器保存并按规则自动携带的小段数据；Session 通常指服务端保存会话状态，Cookie 只存会话 ID；Token 是客户端持有的访问凭证，可以是有状态随机串，也可以是 JWT。它们不是互斥概念，JWT 也可以存入 Cookie。

### 78. HTTPS 提供了什么？

**回答：** TLS 为传输提供机密性、完整性和服务端身份认证，客户端证书还可提供双向认证。它不能自动保证服务端业务安全，也不能防止终端本身被攻破。

分别理解三件事：加密让旁观者难以读懂内容；完整性校验让篡改可被发现；证书验证降低你连接到冒牌服务的风险。HTTPS 不会阻止服务端发生 SQL 注入，也不会阻止已登录用户越权读取他人数据，因为这些属于应用层安全。

### 79. TLS 握手的大致过程是什么？

**回答：** 客户端发送支持的版本、算法和随机参数；服务端选择参数并发送证书；客户端验证证书链和域名；双方通过密钥交换得到会话密钥；之后使用对称加密传输应用数据。TLS 1.3 减少了握手往返并移除了部分旧算法。

### 80. 数字证书解决什么问题？

**回答：** 证书把域名等身份与公钥绑定，并由受信任 CA 签名。浏览器验证证书链、有效期、域名和吊销状态，从而降低中间人伪装服务端的风险。证书本身不用于加密整个大文件。

如果服务端只发来一个公钥，客户端无法判断它属于真正的网站还是中间人。证书相当于由受信任机构签发的“公钥身份证”：其中包含主体、域名、公钥、有效期和签发者等信息。浏览器沿证书链验证到本地信任的根证书，才接受这次身份绑定。

### 81. DNS 解析过程是什么？

**回答：** 浏览器和操作系统先查本地缓存，再询问递归解析器；若无缓存，解析器从根、顶级域和权威 DNS 逐级获取结果，并按 TTL 缓存。实际系统可能使用 CNAME、负载均衡和 CDN 调度。

### 82. 正向代理和反向代理有什么区别？

**回答：** 正向代理代表客户端访问外部服务，服务端通常看到代理；反向代理代表服务端接收请求，客户端不必知道真实后端。Nginx 常用于反向代理、TLS 终止、负载均衡、静态文件和缓存。

### 83. CDN 为什么能加速？

**回答：** CDN 把可缓存内容放到靠近用户的边缘节点，减少网络距离和源站压力，并可进行连接优化与安全防护。动态内容仍可能回源；缓存键、过期和刷新策略设计不当会造成旧数据或命中率低。

### 84. 长轮询、SSE 和 WebSocket 有什么区别？

**回答：** 长轮询由客户端发请求，服务端等到有数据或超时后返回，再立即发下一次；SSE 在一个 HTTP 响应上持续推送文本事件；WebSocket 建立全双工通道。通知和模型输出适合 SSE，双向高频交互适合 WebSocket。

### 85. IP 地址、MAC 地址和 ARP 分别做什么？

**回答：** IP 地址用于跨网络的逻辑寻址和路由，MAC 地址用于本地链路交付。主机知道同网段目标 IP 后，通常通过 ARP 查询对应 MAC；跨网段时先把帧交给默认网关。路由过程中 IP 端点通常保持不变，而每一跳链路层地址会改变，NAT 是另一个会改写地址的机制。

### 86. 子网掩码、默认网关和 NAT 是什么？

**回答：** 子网掩码用于判断目标是否在本地网段；不在本地时把包交给默认网关。NAT 在网络边界转换内外地址和端口，让多个内网主机共享公网地址，也隐藏了内部拓扑。NAT 不等于防火墙，入站访问仍需端口映射和安全策略。

### 87. MTU 和 MSS 有什么区别？

**回答：** MTU 是链路层单个帧可承载的最大网络层包大小；TCP MSS 是 TCP 报文段中应用数据的最大长度，通常由 MTU 减去 IP 和 TCP 头部得到。尺寸过大会分片或丢包，路径 MTU 发现失效时可能出现“能握手但大响应卡住”的问题。

### 88. TCP 超时重传和快速重传有什么区别？

**回答：** 超时重传依靠动态估计的 RTO，在确认长期未到达时重发；快速重传通常在收到多个重复 ACK 后推断中间报文丢失，不必等超时。重传会与拥塞控制协同，应用层随意重试不能替代传输层可靠性，也可能造成重复业务操作。

### 89. 滑动窗口如何提高 TCP 吞吐？

**回答：** 发送方无需每发一个报文都停下等 ACK，而是在窗口允许范围内连续发送多个字节。接收窗口反映接收端缓冲能力，拥塞窗口反映网络承载估计，实际可发送量受两者较小值限制。窗口扩大选项用于高带宽时延积链路。

### 90. TCP Keepalive 和应用层心跳有什么区别？

**回答：** TCP Keepalive 由内核在连接长时间空闲后探测对端是否仍可达，默认周期往往较长；应用层心跳可携带业务语义，并按产品需要更快发现半开连接。两者都要考虑移动网络、代理空闲超时和误判，不能把“连接还活着”理解成“业务处理正常”。

### 91. QUIC 为什么能改善 HTTP/3？

**回答：** QUIC 在 UDP 之上于用户态实现可靠传输、TLS 1.3 和多路流。不同流独立处理丢包，避免 HTTP/2 在单个 TCP 连接上的传输层队头阻塞；连接 ID 还支持网络切换后的连接迁移。代价是实现复杂、加密开销和中间设备兼容性问题。

### 92. HTTP 方法中的安全和幂等是什么意思？

**回答：** 安全表示方法语义上只读，不应改变服务端资源，例如 GET、HEAD；幂等表示同一请求执行多次的预期效果与执行一次相同，例如 PUT、DELETE。POST 通常不幂等，但可以用幂等键实现业务幂等。网络重试策略应依据实际业务，而不是只看方法名。

### 93. `Content-Length`、分块传输和流式响应有什么关系？

**回答：** 已知完整响应大小时可发送 `Content-Length`；HTTP/1.1 不预先知道大小时可用 chunked 编码分块发送。HTTP/2 和 HTTP/3 有自己的帧结构，不使用 HTTP/1.1 的 chunked 语法。流式响应还要避免代理缓冲，并处理客户端断开和背压。

### 94. WebSocket 握手如何完成？

**回答：** 客户端先发带 `Upgrade: websocket` 等头部的 HTTP/1.1 请求，服务端返回 `101 Switching Protocols` 并校验派生值，随后同一 TCP 连接切换为 WebSocket 帧协议。建立后可双向传输文本或二进制帧，但鉴权、心跳、重连和扩容需要应用自己设计。

### 95. CORS 和预检请求是什么？

**回答：** CORS 是浏览器对跨源脚本请求执行的访问控制机制。非简单请求通常先发送 `OPTIONS` 预检，询问服务端是否允许来源、方法和请求头。CORS 不是服务端鉴权，也不会阻止 curl 或后端服务发请求；带凭证时来源不能配置为通配符。

### 96. 四层和七层负载均衡有什么区别？

**回答：** 四层负载均衡依据 IP、端口和传输连接转发，协议通用、开销较低；七层理解 HTTP 等应用协议，可按域名、路径、Header 或 Cookie 路由，也能做 TLS 终止、缓存和限流。七层能力更丰富，但处理成本和配置复杂度更高。

## 四、数据库基础

### 数据库要解决“查得快”和“改得对”两类问题

索引、执行计划和连接算法让查询更快；事务、锁、MVCC 和日志让并发修改与故障恢复保持可接受的正确性。优化读性能可能增加索引维护成本，提高隔离级别可能降低并发，因此数据库几乎所有题目都包含取舍。

把 B+ 树想成一本多级目录：内部页只告诉你下一页去哪里，叶子页才保存有序记录；把 MVCC 想成给记录保留历史版本，让读者看到适合自己事务时间点的版本。类比用于建立直觉，最终还要回到执行计划、版本链和锁范围。

### 97. 关系型数据库和 NoSQL 如何选择？

**回答：** 关系型数据库擅长结构化关系、事务、约束和复杂查询；NoSQL 是多类系统的统称，可针对键值、文档、列族或图关系优化扩展和访问模式。选型应从数据模型、一致性、查询和运维需求出发，不能简单按“数据量大”决定。

### 98. 数据库三大范式是什么？

**回答：** 第一范式要求属性原子；第二范式要求非主属性完全依赖候选键；第三范式要求非主属性不传递依赖候选键。范式减少冗余和更新异常，读性能要求高时也可有意识反范式，但要承担一致性维护成本。

### 99. 主键、唯一索引和普通索引有什么区别？

**回答：** 主键唯一且非空，用于标识一行；唯一索引保证列组合不重复，NULL 行为取决于数据库；普通索引用于加速查询但不保证唯一。索引能加速读取，也会占空间并增加写入维护成本。

### 100. 索引为什么会失效或不被选择？

**回答：** 常见原因包括不满足联合索引前缀、对索引列做函数或隐式类型转换、前导模糊匹配、选择性太低、数据量很小，或优化器判断全表扫描成本更低。应以执行计划和实际统计为准。

“有索引”不代表“使用索引一定更便宜”。如果一个字段只有男女两种值，查询其中一类可能仍要访问表中一半记录，走二级索引再回表反而比顺序扫描更贵。排查时先看 `EXPLAIN` 或 `EXPLAIN ANALYZE`，比较预计行数与实际行数，再检查统计信息、条件写法和索引顺序。

**易错点：** 不要把所有没有使用索引的情况都叫“索引失效”。有时索引完全可用，只是优化器基于成本主动没有选择它。

### 101. 事务隔离解决哪些问题？

**回答：** 脏读是读到未提交数据；不可重复读是同一事务两次读同一行结果不同；幻读是按条件两次查询出现或消失了记录。更高隔离级别减少异常，但可能增加锁、冲突和重试。

用“统计本月账单”来理解：如果读到了另一个事务随后回滚的账单，就是脏读；同一条账单金额第一次是 100、第二次变成 120，是不可重复读；两次查询“金额大于 100 的账单”，第二次多出一行，是幻读。区别在于前两者关注某条记录的版本，幻读关注满足条件的记录集合。

隔离级别不是越高越好。串行化最容易推理，但可能让大量事务互相等待；实际系统要根据一致性要求、冲突频率和重试成本选择。

### 102. 乐观锁和悲观锁是什么？

**回答：** 悲观锁先锁住资源再操作，适合冲突频繁且事务短的场景；乐观锁读取时不加排他锁，更新时检查版本号，冲突后重试或提示用户，适合冲突较少的场景。

```sql
UPDATE account
SET balance = ?, version = version + 1
WHERE id = ? AND version = ?;
```

受影响行数为 0 表示版本冲突。

### 103. undo log、redo log、binlog 分别做什么？

**回答：** 在 MySQL/InnoDB 中，undo log 支持回滚和 MVCC 旧版本；redo log 记录页修改，用于崩溃恢复和持久性；binlog 是 Server 层逻辑日志，用于复制和时间点恢复。它们层次和用途不同。

可以用三个方向记忆：undo 面向“往回走”，事务失败时撤销，也让快照读找到旧版本；redo 面向“重新做”，数据页还没落盘就崩溃时，可重放已经提交的修改；binlog 面向“把变化交给别处”，供主从复制、审计和时间点恢复使用。不能用其中一个简单替代另外两个。

### 104. 为什么不建议深分页？

**回答：** `LIMIT 100000, 20` 通常需要扫描并丢弃前面大量记录，数据变动还可能造成重复和遗漏。可使用基于稳定排序键的游标分页，例如记住上一页最后的 `(created_at, id)`。

游标分页不是记录“第几页”，而是记录“上一页停在哪里”。例如按 `(created_at DESC, id DESC)` 排序，下一页查询比最后一条记录更早的数据。`id` 用于在时间相同的情况下提供唯一顺序，否则仍可能重复或漏数据。它适合连续向后翻页，但不擅长直接跳到第 5000 页。

### 105. 数据库连接池解决什么问题？

**回答：** 建立数据库连接成本较高，连接池复用连接并限制并发，避免每个请求都新建连接，也保护数据库不被过多连接压垮。池耗尽通常说明慢查询、事务过长、连接泄漏或容量不匹配。

连接池可以理解为餐厅固定数量的座位：座位太少会让请求排队，座位太多又会让厨房也就是数据库同时处理过多任务，增加锁竞争和内存压力。总连接数还要乘以应用实例数量；10 个实例每个池 50 条连接，数据库看到的上限可能是 500，而不是 50。

### 106. 一条 SQL 查询大致怎样执行？

**回答：** 服务端完成连接与权限检查后解析 SQL，构建语法树；优化器根据统计信息、索引和成本选择连接顺序与访问路径；执行器调用存储引擎读取数据，完成过滤、聚合、排序并返回。排查时重点看执行计划的实际行数、扫描方式、回表、临时表和排序，而不是只背固定规则。

### 107. `WHERE` 和 `HAVING` 有什么区别？

**回答：** `WHERE` 在分组和聚合前过滤行，通常更早减少数据量并可使用索引；`HAVING` 在分组后过滤组，可引用聚合结果。没有聚合时部分数据库也允许 `HAVING`，但表达和优化通常不如正确使用 `WHERE` 清晰。

### 108. 常见 JOIN 有什么区别？

**回答：** `INNER JOIN` 只保留两侧匹配行；`LEFT JOIN` 保留左表全部行，右侧无匹配时补 NULL；`RIGHT JOIN` 方向相反；`FULL OUTER JOIN` 保留两侧全部行，但 MySQL 不直接支持。连接条件缺失会产生笛卡尔积，连接列缺索引或估算错误会显著放大成本。

### 109. 联合索引为什么强调最左前缀？

**回答：** B+ 树联合索引按列顺序形成字典序。索引 `(a,b,c)` 可以直接利用 `a`、`a,b`、`a,b,c` 的连续前缀；跳过 `a` 后，整棵树并不按 `b` 全局有序。范围条件后的列能否继续用于定位、过滤或覆盖，要结合数据库版本和执行计划判断。

想象电话簿先按姓、再按名排序。知道姓“李”，就能在李姓区域继续按名字查；如果只知道名字“明”，这个名字会散落在不同姓氏区域，无法直接定位一个连续范围。联合索引列顺序也应根据等值条件、范围条件、排序和选择性共同设计，而不是机械地把选择性最高的列永远放第一位。

### 110. 什么是覆盖索引和回表？

**回答：** 查询需要的列都能从某个索引取得时称为覆盖索引，可避免再访问数据页。InnoDB 二级索引叶子包含索引列和主键，若还需要其他列，就用主键到聚簇索引查询，这叫回表。覆盖索引能减少 I/O，但把太多列塞进索引会增加空间和写成本。

### 111. 索引下推是什么？

**回答：** 索引下推允许存储引擎在扫描索引记录时先判断可用的条件，过滤不符合的记录，再决定是否回表，从而减少回表次数。它与“条件能否缩小索引扫描范围”不同；执行计划中的提示和实际扫描行数更能说明效果。

### 112. InnoDB 的聚簇索引和二级索引如何关联？

**回答：** InnoDB 聚簇索引叶子保存整行数据，通常使用主键组织；二级索引叶子保存二级键和对应主键，再通过主键回到聚簇索引。主键过长会被复制到每个二级索引，增加空间和缓存压力，因此主键通常应稳定、非空且尽量紧凑。

### 113. MVCC 中的快照读和当前读是什么？

**回答：** 普通一致性查询通常根据 Read View 和版本链读取符合可见性规则的历史版本，属于快照读；加锁查询、更新和删除需要查看并操作当前最新记录，属于当前读。具体 Read View 创建时机和锁范围取决于隔离级别与数据库实现。

快照读像查看某个时刻拍下的账本照片，其他事务继续修改时，你仍能沿版本链看到符合自己视图的版本；当前读是要真正修改账本，因此必须面对最新状态并加锁。MVCC 减少了普通读与写的互相阻塞，但不意味着所有读都不加锁，也不消除写写冲突。

### 114. 记录锁、间隙锁和 Next-Key Lock 有什么区别？

**回答：** 记录锁锁住索引记录；间隙锁锁住索引值之间的范围，阻止新记录插入；Next-Key Lock 通常是记录锁与前方间隙锁的组合。InnoDB 在范围加锁时用它减少幻读。是否出现间隙锁与隔离级别、唯一索引等值查询和实际扫描范围有关。

### 115. 数据库死锁如何定位和处理？

**回答：** 死锁是多个事务形成循环等待。数据库会检测并回滚其中一个事务，应用必须能识别并有限重试。定位时查看死锁日志、涉及 SQL、索引和锁顺序；治理手段包括统一访问顺序、缩短事务、减少扫描范围、补合适索引和避免事务中等待外部调用。

### 116. 自增主键和 UUID 如何选择？

**回答：** 自增整数短、顺序写入友好，索引紧凑，但在分布式生成、数据合并和对外暴露时有局限。随机 UUID 可独立生成但较长且插入位置分散，可能增加页分裂和二级索引空间。可根据系统需要选择有序 UUID、雪花 ID 或内部自增键加外部随机 ID。

### 117. 主从复制能否提供强一致读？

**回答：** 异步复制下，主库提交成功时从库可能尚未重放日志，立即读从库可能得到旧数据。可让关键读走主库、等待复制位点、使用半同步机制，或让用户会话在写后一段时间保持主库读取。读写分离提高容量，但必须显式处理复制延迟和故障切换。

### 118. `DELETE`、`TRUNCATE` 和 `DROP` 有什么区别？

**回答：** `DELETE` 按行删除，可带条件并触发行级逻辑；`TRUNCATE` 清空整表，通常走更轻的结构操作，权限和回滚行为依数据库而异；`DROP` 删除表定义及数据。生产操作前应确认事务语义、外键、审计、备份和恢复路径，不能只按“谁更快”选择。

## 五、编程语言与运行时

这一节关注源码到运行结果之间发生了什么：类型系统在何时发现错误，运行时怎样分配和回收对象，序列化怎样跨越进程边界。面试中最好明确具体实现，例如“CPython 主要使用引用计数并处理循环引用”，不要把某个实现细节说成所有 Python 的语言规则。

### 119. 编译型和解释型语言有什么区别？

**回答：** 编译是把源代码提前转换为目标代码；解释是运行时逐步执行某种中间表示或源代码。现代语言常混合使用，例如 JavaScript 引擎会解释并即时编译热点代码，Python 通常先编译成字节码再由虚拟机执行。这个分类不是绝对二分。

### 120. 静态类型和动态类型是什么？

**回答：** 静态类型在运行前进行主要类型检查，动态类型在运行时确定值和操作是否合法。TypeScript 提供静态检查，但类型在编译后大多被擦除，因此外部输入仍需运行时校验。

### 121. 什么是垃圾回收？

**回答：** 垃圾回收自动识别不再可达的对象并回收内存。常见思想包括引用计数和追踪式标记清除；现代运行时还会基于对象“多数朝生夕死”的规律做分代回收。GC 减少手动释放错误，但仍可能有停顿、内存峰值和逻辑泄漏。

### 122. 内存泄漏是什么意思？

**回答：** 程序不再需要某块内存，但它仍被引用或无法释放，导致占用持续增长。前端常见来源有未清理定时器、事件监听、闭包和无限缓存；服务端常见来源有全局集合、连接未关闭和无界队列。

### 123. 深拷贝和浅拷贝有什么区别？

**回答：** 浅拷贝只复制第一层，嵌套对象仍共享引用；深拷贝递归复制整个对象图。深拷贝要处理循环引用、日期、Map、Set、原型和函数等，JSON 序列化不是通用深拷贝方案。

### 124. 序列化和反序列化是什么？

**回答：** 序列化把内存对象转换为可存储或传输的格式，反序列化则恢复。JSON 可读性和兼容性好，但类型表达有限；Protobuf 体积小、解析快且有 Schema，但调试和演进需要规范。反序列化不可信数据必须校验，某些原生对象格式还可能导致代码执行风险。

## 六、Linux 与工程基础

Linux 排障不要从命令清单开始，而要从资源维度开始：CPU 是否忙、内存是否持续增长、磁盘和网络是否等待、文件描述符或连接是否耗尽。每条命令只是观察某个维度的工具。先提出假设，再选证据，最后验证修复是否有效。

### 125. 文件描述符是什么？

**回答：** 文件描述符是进程访问文件、Socket、管道等内核对象的整数句柄。每个进程有描述符表。连接泄漏往往表现为文件描述符耗尽，因此服务要正确关闭资源并监控上限。

### 126. Linux 文件权限如何理解？

**回答：** 权限分为所有者、所属组和其他用户的读、写、执行。目录的读表示列出名称，写表示增删目录项，执行表示进入和访问其中路径。服务应使用专用低权限用户运行。

`rwxr-x---` 可按三组读：所有者 `rwx`，组用户 `r-x`，其他用户没有权限。目录权限最容易混淆：文件能否删除主要取决于父目录的写和执行权限，不只取决于文件自己的写权限。数字表示中 `r=4、w=2、x=1`，所以 `750` 对应上述权限。

### 127. 软链接和硬链接有什么区别？

**回答：** 硬链接是同一个 inode 的另一个目录项，通常不能跨文件系统，也通常不允许指向目录；软链接是保存目标路径的独立文件，可以跨文件系统，但目标删除后会失效。

把 inode 想成文件实体，文件名只是指向实体的标签。硬链接是再贴一个标签，删除其中一个名称，实体仍可通过另一个名称访问；软链接则像写着“目标在某路径”的便签，目标移动或删除后便签会断。由此也能推出为什么硬链接通常不能跨文件系统。

### 128. 如何排查服务 CPU 很高？

**回答：** 先确认是哪个进程和线程，再结合应用指标、火焰图或采样分析定位热点；同时检查是否有死循环、序列化、正则回溯、GC 或异常重试。不要在没有证据时直接扩容。

推荐顺序是：确认问题发生时间和范围 → 找到高 CPU 进程与线程 → 采样调用栈或生成火焰图 → 对照发布、流量和日志变化 → 修复后用同样负载复测。CPU 满也可能只是症状，例如下游失败触发无上限重试；只增加机器会暂时掩盖根因。

### 129. 如何排查内存持续增长？

**回答：** 先区分进程常驻内存、堆、缓存和系统页缓存；观察增长是否最终稳定；获取堆快照或分配剖析，比较对象类型和引用链；检查无界缓存、队列、连接和监听器。修复后用相同流量复测。

### 130. 负载均衡有哪些策略？

**回答：** 常见有轮询、加权轮询、最少连接、随机和一致性哈希。无状态服务容易水平扩展；需要粘性会话时可按 Cookie 或哈希路由，但更推荐把会话放到共享存储，减少实例绑定。

### 131. 健康检查为什么分存活和就绪？

**回答：** 存活检查判断进程是否需要重启；就绪检查判断实例是否可以接收流量。应用启动中、正在优雅关闭或关键依赖不可用时，可以仍然存活但暂时不就绪。

例如应用正在加载模型，此时进程正常运行，不应因存活检查失败而反复重启；但它还不能服务请求，所以就绪检查应失败，让负载均衡暂不分配流量。反过来，如果事件循环彻底卡死，存活检查失败才适合触发重启。把两者混成一个检查容易形成重启风暴。

### 132. 栈溢出和堆内存不足有什么区别？

**回答：** 栈溢出通常来自递归过深、过大的栈上对象或调用链异常，每个线程的栈空间有限；堆内存不足来自活跃对象、泄漏、无界缓存或分配峰值超过限制。二者的错误表现、诊断工具和修复方式不同，不能都简单归为“内存不够”。

### 133. GC 中的可达性和分代思想是什么？

**回答：** 追踪式 GC 从根对象出发标记仍可访问的对象，其余可回收。分代建立在“大多数对象很快死亡”的经验上，新生代更频繁回收，存活较久的对象晋升到老年代。写屏障和记忆集用于跟踪跨代引用，减少每次扫描整个堆。

### 134. 什么是 JIT？它为什么会有预热？

**回答：** 即时编译器在运行时收集类型和热点信息，把频繁执行的代码编译成优化机器码。优化依赖假设，假设失效时可能去优化回退。程序刚启动时热点信息不足且要承担编译成本，所以短任务与长期服务的性能特征不同，基准测试需要预热并固定环境。

### 135. Linux 信号中 `SIGTERM` 和 `SIGKILL` 有什么区别？

**回答：** `SIGTERM` 可被进程捕获，用于停止接流量、完成在途请求和释放资源；`SIGKILL` 由内核立即终止，进程无法捕获或清理。部署系统通常先发 TERM，超过宽限期再发 KILL，因此应用必须实现有截止时间的优雅关闭。

### 136. `top` 中的负载平均值是什么？

**回答：** Linux load average 表示一段时间内处于可运行状态以及不可中断睡眠状态的任务平均数量，不等同于 CPU 使用率。应结合 CPU 核数、`us/sy/iowait`、运行队列、磁盘和容器配额判断。高负载可能来自 CPU 饱和，也可能来自 I/O 等待。

### 137. 如何排查端口和连接问题？

**回答：** 先确认进程是否监听正确地址和端口，再检查本机防火墙、安全组、DNS、路由和代理；使用 `ss` 查看监听与连接状态，`lsof` 查端口所属进程，`curl` 或 `nc` 做分层连通测试。若连接数异常，再看 SYN、ESTABLISHED、TIME_WAIT 和文件描述符上限。

### 138. 日志文件删除后磁盘空间为什么可能没有释放？

**回答：** Linux 删除目录项后，如果进程仍持有文件描述符，对应 inode 和数据块仍不会回收。可用 `lsof` 查找已删除但仍打开的文件，让进程重新打开日志或重启。生产日志应使用正确的轮转与 reopen 机制，避免直接删除正在写入的大文件。

## 七、分布式系统基础

### 分布式系统的困难来自“节点之间无法立即知道同一件事”

网络会延迟、丢包或分区，节点也可能在任意时刻重启。因此远程调用不能等同于本地函数：超时后你甚至不知道对方是没执行，还是执行成功但响应丢了。幂等、重试、租约、共识和消息确认都在处理这种“不确定”。

学习 CAP、最终一致和分布式事务时，先描述故障场景，再讨论选择。脱离网络分区、业务容忍度和恢复时间，只说系统属于 CP 或 AP，通常没有实际意义。

### 139. CAP 定理是什么？

**回答：** 当网络分区发生时，分布式系统无法同时保证强一致性和每个请求都获得成功响应，只能在一致性与可用性之间取舍。CAP 讨论的是分区条件下的选择，不是平时简单地“三选二”。

### 140. 强一致、最终一致分别是什么？

**回答：** 强一致让读操作像访问单一最新副本；最终一致允许副本短时间不同，但没有新写入时最终会收敛。订单支付等关键状态倾向更强的一致性，点赞数和缓存常可接受最终一致。

### 141. 什么是 BASE？

**回答：** BASE 通常指基本可用、软状态和最终一致，是很多分布式系统在高可用和扩展性下采用的思路。它不是放弃一致性，而是让一致性级别匹配业务需求。

例如用户修改头像后，个人页立即看到新头像，但评论区的 CDN 缓存几秒后才更新，这可能是可接受的最终一致；扣款金额和账户余额则通常不能随意展示相互矛盾的状态。是否采用最终一致由具体业务不变量决定，不能把 BASE 当成所有 NoSQL 系统的免责口号。

### 142. 消息队列有什么作用？

**回答：** 异步解耦、削峰填谷和事件广播。它会引入重复、延迟、积压、顺序和失败处理问题。生产者成功写业务数据却没发出消息时，可用事务消息或 Outbox Pattern 改善一致性。

### 143. 消息为什么可能重复？

**回答：** 消费者处理成功后，在确认消息前崩溃，队列会再次投递。多数系统更现实的语义是至少一次投递，因此消费者必须以业务键实现幂等。所谓“恰好一次”通常只在特定边界和约束内成立。

### 144. Outbox Pattern 是什么？

**回答：** 在同一个数据库事务中同时写业务表和 outbox 事件表，后台发布器再把事件发送到消息系统并记录发布状态。这样避免“数据库提交成功但消息发送失败”的双写不一致，消费者仍需幂等。

### 145. 分布式锁适合解决什么问题？

**回答：** 它用于协调多个进程对共享资源的互斥访问，例如避免同一任务被同时执行。锁需要唯一持有者标识、租约、超时和安全释放；业务正确性还应有唯一约束或版本检查兜底，因为网络分区和暂停可能让旧持有者在租约过期后继续运行。

### 146. 什么是一致性哈希？

**回答：** 把节点和键映射到环上，键落到顺时针最近节点。增加或删除节点时只迁移部分键，适合缓存分片。虚拟节点可以改善数据分布不均。

普通取模 `hash(key) % N` 在 N 改变时会让大量 Key 重新映射，缓存几乎同时失效；一致性哈希只影响新增或离开节点附近的一段区间。真实节点性能不同或分布不均时，可给一个物理节点放置多个虚拟节点，并通过虚拟节点数量调节权重。

### 147. 什么是服务降级、限流、熔断？

**回答：** 限流控制进入系统的请求量；熔断在下游持续失败时快速失败；降级在资源不足或依赖故障时关闭非核心能力或返回简化结果。三者共同防止局部故障扩散。

可以按时序记忆：流量进门前先限流；调用下游时由熔断器阻止继续堆积失败；无法提供完整功能时用降级结果维持核心链路。例如 AI 分析服务故障时，限制新分析任务、熔断模型调用，同时仍返回数据库中的基础统计。它们解决的阶段不同，常组合使用。

### 148. CAP 和 PACELC 分别说明什么？

**回答：** CAP 说明网络分区发生时，分布式系统无法同时保证强一致和每个请求都成功响应；PACELC 进一步提醒：没有分区时也要在延迟与一致性之间取舍。它们用于理解设计边界，不是给整个产品简单贴 CP 或 AP 标签，具体读写路径可能选择不同。

### 149. 什么是共识？它和数据一致性有什么区别？

**回答：** 共识让多个节点对某个值或日志顺序达成一致，Raft、Paxos 是典型算法；一致性模型描述客户端能观察到哪些读写结果，例如线性一致、因果一致和最终一致。共识可用于实现强一致复制，但两者不是同一个概念。

### 150. Raft 的核心过程是什么？

**回答：** 节点在跟随者、候选者和领导者之间转换；超时后发起选举，获得多数票成为领导者；写入先追加到领导者日志，再复制到多数节点后提交，并按相同顺序应用到状态机。任期、日志匹配和多数派共同避免出现两个都能提交冲突日志的领导者。

### 151. 2PC、TCC 和 Saga 有什么区别？

**回答：** 2PC 由协调者让参与者先准备再统一提交，能提供较强原子性但会阻塞并依赖协调者与资源锁；TCC 把业务显式拆为 Try、Confirm、Cancel，控制强但开发成本高；Saga 把长事务拆成局部事务并为每步设计补偿，适合长流程，但补偿不一定能完全恢复现实世界状态。

### 152. 什么是租约和 fencing token？

**回答：** 租约授予客户端一段有限时间的权利，但客户端暂停、网络延迟或时钟问题可能让过期持有者继续操作。fencing token 为每次新租约生成递增编号，下游只接受更大的编号，从资源端拒绝旧持有者写入，比只依赖锁的过期时间更稳妥。

### 153. 消息的至多一次、至少一次和恰好一次是什么？

**回答：** 至多一次可能丢但不重复；至少一次通过重投降低丢失风险，但消费者可能收到重复；端到端恰好一次很难，需要消息系统、状态存储和业务副作用共同配合。工程中常用至少一次投递加业务幂等，明确确认时机和失败窗口。

### 154. 如何保证消息顺序？

**回答：** 全局顺序会限制吞吐，通常只要求同一业务键局部有序。生产者按订单或用户 ID 路由到同一分区，分区内单线程或按序消费；失败重试不能绕过前一条消息。扩缩分区、并发消费和死信处理都可能破坏顺序，需要在设计中说明。

### 155. 什么是背压？

**回答：** 当生产速度超过消费速度时，系统应向上游传递压力，而不是无限缓存。可以限制队列长度、暂停读取、降低并发、丢弃低价值数据或返回过载错误。没有背压的异步系统看似解耦，实际会把延迟和内存风险藏进队列。

### 156. 分布式 ID 怎样设计？

**回答：** 数据库自增简单但中心化；UUID 去中心但较长且随机版本不利于有序索引；Snowflake 类方案用时间戳、节点号和序列生成趋势递增 ID，需处理时钟回拨、节点号冲突和位数寿命。ID 是否可枚举、是否需要按时间排序也应纳入选择。

### 157. 缓存热点 Key 和大 Key 有什么风险？

**回答：** 热点 Key 会让请求集中到单个分片，可能压垮一个节点；可用本地缓存、请求合并、只读副本或拆分 Key。大 Key 会占用网络和单线程处理时间，删除时也可能产生抖动；应限制结构大小、分批读写并使用异步删除能力。

## 八、安全基础

### 安全不是某一个加密算法，而是一条信任链

加密保护内容不被看见，哈希帮助检测变化，签名证明消息来自私钥持有者，证书再把公钥与身份绑定。到了应用层，还要继续做认证、授权、输入校验、最小权限和审计。任何一层缺失，都可能让底层密码学失去意义。

记住一个基本原则：**所有跨越信任边界的数据都不可信。** 用户输入、Webhook、检索文档和下游响应都要校验；CORS、前端隐藏按钮和 Prompt 都不能代替服务端权限控制。

### 158. 对称加密和非对称加密有什么区别？

**回答：** 对称加密使用同一密钥加解密，速度快，适合大量数据；非对称加密使用公私钥，适合密钥交换和数字签名，但计算更贵。TLS 通常用非对称机制完成身份认证和密钥协商，再用对称密钥传输数据。

### 159. 哈希、加密、编码有什么区别？

**回答：** 哈希是单向摘要，用于完整性和索引等；加密使用密钥并可解密，用于保密；编码只改变表示形式，便于传输，不提供安全性。Base64 不是加密。

同一输入通常得到固定哈希摘要，目标不是还原原文；加密后的密文应能由持有正确密钥的一方恢复；编码只是约定字符怎样表示字节，任何人都能按规则解码。密码存储使用专用密码哈希，HTTPS 使用加密，邮件附件常使用 Base64 编码，三个场景不能互换。

### 160. 数字签名解决什么问题？

**回答：** 发送方用私钥对消息摘要签名，接收方用公钥验证，从而确认消息未被篡改，并验证签名者持有对应私钥。数字签名通常不负责隐藏消息内容。

签名可以类比封条加署名：内容仍可能公开，但别人改动后验证会失败。签名能证明“持有该私钥的一方认可了这份消息”，至于这个公钥究竟属于谁，还需要证书或其他可信分发方式建立身份绑定。签名与加密可以同时使用，但解决的是不同问题。

### 161. 什么是最小权限原则？

**回答：** 用户、服务和凭证只拥有完成当前任务所需的最少权限，并限制作用范围和有效时间。例如分析服务只读账单表，模型工具不能直接执行任意 SQL，生产密钥不能用于本地开发。

### 162. SSRF 是什么？

**回答：** 攻击者诱导服务端请求其指定地址，从而访问内网、云元数据或其他受保护资源。防护包括目标域名白名单、解析后校验 IP、禁止私网和特殊协议、限制重定向，并隔离出站网络权限。

### 163. 重放攻击是什么？

**回答：** 攻击者截获合法请求后再次发送，以重复执行操作。可以使用 TLS、防重放 nonce、时间戳、短有效期、签名和服务端幂等记录。支付和写接口尤其需要业务唯一号。

即使攻击者不知道签名密钥，已经签好的合法请求在有效期内仍可能被原样重发。时间戳限制旧请求，nonce 保证每次请求唯一，服务端再记录已使用 nonce 或业务单号。单独使用时间戳仍允许在有效窗口内快速重放，因此通常需要组合机制。

### 164. OAuth 2.0 和 OpenID Connect 解决什么问题？

**回答：** OAuth 2.0 是授权框架，让客户端在限定范围内代表用户访问资源；OIDC 在其上增加身份层，通过 ID Token 和标准端点完成登录。OAuth Access Token 不是天然的登录身份证明。公开客户端应使用授权码加 PKCE，避免把长期密钥放在前端。

### 165. JWT 和不透明 Token 如何选择？

**回答：** JWT 可由资源服务本地验证，减少每次查询认证中心，但即时撤销、权限变化和令牌体积处理更复杂；不透明 Token 本身无业务含义，服务端通过会话表或 introspection 查询状态，更易撤销但增加存储或网络访问。选择取决于拓扑、撤销时效和风险。

### 166. 密码哈希为什么需要盐和慢算法？

**回答：** 每个密码使用独立随机盐，可让相同密码得到不同摘要并抵抗预计算表；Argon2id、scrypt、bcrypt 等故意消耗时间和内存，提高离线暴力破解成本。不能使用普通快速哈希直接存密码，还应支持参数升级、登录限速和多因素认证。

### 167. CSP 能如何缓解 XSS？

**回答：** 内容安全策略限制脚本、样式、图片等资源允许从哪里加载，并可用 nonce 或 hash 允许特定内联脚本，从而降低注入内容被执行的机会。CSP 是纵深防御，仍应做上下文正确的输出编码、避免危险 DOM API，并及时修复注入点。

### 168. CORS 为什么不是安全认证机制？

**回答：** CORS 由浏览器限制网页脚本读取跨源响应，非浏览器客户端不受它约束，某些简单请求甚至仍会发送到服务端。接口必须独立完成身份认证、权限校验和 CSRF 防护，不能因为只允许某个 Origin 就相信请求者。

## 九、综合场景题

场景题建议按“目标 → 约束 → 正常流程 → 失败流程 → 观测指标”回答。例如设计扣库存系统，不仅要说原子更新，还要解释重复请求、数据库失败、消息重投和如何发现库存异常。面试官通常更关心你有没有想到边界，而不是画了多少组件。

### 169. 一个接口突然变慢，如何排查？

按从现象到依赖的顺序回答：

1. 看错误率、P95/P99、吞吐和变慢时间范围，确认是单接口、单实例还是全局。
2. 用 Trace 拆分网关、应用、数据库、Redis和外部 API 耗时。
3. 检查 CPU、内存、GC、事件循环延迟、线程/连接池和队列。
4. 对慢 SQL 看执行计划和锁等待，对外部服务看超时与重试。
5. 对比最近发布、配置和流量变化。
6. 先限流、降级或回滚止损，再验证根因和修复效果。

### 170. 高并发扣库存怎样避免超卖？

**回答：** 把判断和扣减放在数据库原子条件更新中，例如 `UPDATE ... SET stock = stock - 1 WHERE id = ? AND stock > 0`，根据受影响行数判断成功。还要用业务订单号保证幂等。Redis 预扣可以提高吞吐，但需要处理缓存与数据库一致性、补偿和重复消息。

### 171. 如何设计一个短链接系统？

**回答：** 写入时生成唯一短码并保存短码到长 URL 的映射；读取路径高频且简单，可用 Redis 缓存并回源数据库；短码需要足够空间、避免碰撞和被轻易枚举；对恶意链接做审核、限流和过期。访问统计可异步写消息队列，避免阻塞跳转。

### 172. 如何设计任务执行系统？

**回答：** 任务表保存状态、参数、重试次数、租约和幂等键；生产者创建任务后进入队列；Worker 领取任务并周期续租，成功或失败原子更新状态；超时任务可重新投递；重复执行由业务幂等兜底。监控队列积压、执行延迟、失败率和死信。

### 173. 浏览器重复提交表单怎么办？

**回答：** 前端提交中禁用按钮只能改善体验，不能作为正确性保证。服务端为业务操作使用幂等键或唯一业务号，并以数据库唯一约束兜底；重复请求返回第一次的处理结果。

用户双击、页面重试、代理重试都可能造成重复请求，所以“按钮变灰”挡不住所有路径。创建账单时可由客户端生成幂等键，服务端把用户、请求摘要和结果一起保存；相同键但请求内容不同应拒绝。涉及订单或支付时，再用业务唯一约束防止并发穿透应用层检查。

### 174. 缓存与数据库不一致怎么办？

**回答：** 先定义业务允许的不一致窗口。常用 Cache Aside 在数据库提交后删除缓存，并为缓存设置 TTL；删除失败要重试或通过消息处理。强一致场景直接读数据库或使用更严格的同步方案，不应承诺缓存天然强一致。

## 十、面试速记

### 复杂度

- 数组随机访问 `O(1)`，中间插入删除 `O(n)`。
- 哈希表平均查询 `O(1)`，最坏可退化。
- 平衡搜索树操作 `O(log n)`。
- 堆顶 `O(1)`，插入和删除堆顶 `O(log n)`。
- BFS/DFS 为 `O(V + E)`。
- 比较排序下界为 `O(n log n)`。

### 网络

- TCP：可靠、有序、字节流；UDP：无连接、保留报文边界。
- 三次握手同步双方能力和序列号；四次挥手来自双向独立关闭。
- HTTP/2 多路复用仍受 TCP 丢包影响；HTTP/3 基于 QUIC。
- HTTPS = HTTP over TLS；Base64 不是加密。
- SSE 适合单向推送，WebSocket 适合全双工。

### 操作系统

- 进程重隔离，线程重执行，协程重用户态调度。
- 异步提升 I/O 并发，不能自动加速 CPU 计算。
- 死锁四条件：互斥、占有且等待、不可剥夺、循环等待。
- 虚拟内存通过页表映射物理内存，TLB 缓存地址转换。
- `epoll` 适合大量连接、少量活跃的事件驱动服务。

### 数据库与分布式

- 索引加速读，但增加存储和写成本。
- MVCC 让读操作访问合适版本，减少读写阻塞。
- 乐观锁靠版本检查，悲观锁先锁后改。
- 消息系统通常按至少一次投递设计，消费者必须幂等。
- CAP 是网络分区发生时一致性与可用性的取舍。

真正面试时，定义只占前 20 秒。后面的得分来自你能否说清边界、反例和项目中的实际选择。
